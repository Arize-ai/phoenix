# Harbor LangSmith plugin: configuration and lifecycle design

Research date: 2026-08-14. Scope: the official `harbor-langsmith` implementation,
used only as design input for Phoenix's Harbor plugin.

## Finding

LangSmith uses **one public plugin object**, `LangSmithPlugin`; it does not define a
separate configuration class. Its constructor resolves each option immediately using
`explicit_value or os.getenv(...)`, then stores both configuration and job-scoped
mutable state on the plugin instance. The public package exports only the plugin.

Sources: [plugin source](https://github.com/harbor-framework/harbor/blob/ac398bbda7c4c1073461797d3b95c2455cc671b5/packages/harbor-langsmith/src/harbor_langsmith/plugin.py), [package export](https://github.com/harbor-framework/harbor/blob/ac398bbda7c4c1073461797d3b95c2455cc671b5/packages/harbor-langsmith/src/harbor_langsmith/__init__.py), and [plugin README](https://github.com/harbor-framework/harbor/blob/ac398bbda7c4c1073461797d3b95c2455cc671b5/packages/harbor-langsmith/README.md).

## What the plugin does

- Constructor options mirror Harbor plugin kwargs: dataset name, experiment name/id,
  endpoint, API key, workspace, dataset sync, and fail-fast. Explicit values win over
  the matching environment values; booleans deliberately distinguish `None` (read
  environment/default) from `False` (explicitly disable). The README documents both
  constructor kwargs and the environment surface.
- It validates the required API key only in `_setup`, called from `on_job_start`;
  then it constructs the HTTP session and adds the API key to a request header. The
  key is not included in events, metadata, or exception messages generated by the
  plugin.
- `on_job_start` does setup and registers trial lifecycle hooks. Runtime state stays
  private and separate by purpose: session/dataset IDs, example IDs, trial/phase run
  IDs, and timing maps. `on_job_end` closes only an experiment owned by that job;
  reused or named shared experiments stay open.

These behaviors are covered by the upstream [plugin tests](https://github.com/harbor-framework/harbor/blob/ac398bbda7c4c1073461797d3b95c2455cc671b5/packages/harbor-langsmith/tests/unit/test_plugin.py), including required-key validation, explicit/session reuse, hook registration, and session ownership.

## Recommendation for Phoenix

Use a single **public** `PhoenixJobPlugin` and keep its configuration surface in the
constructor plus Phoenix's existing environment resolvers. Phoenix should not copy
LangSmith's ad-hoc `os.getenv` resolution because `phoenix.client.utils.config`
already owns endpoint precedence, normalization, and header/API-key handling.

An internal frozen `_ResolvedPhoenixConfig` becomes useful only once multiple
constructor/environment values must be resolved together or passed to independent
writers. It should be a private value object, created once at job start, with no
runtime IDs or mutable lifecycle state. The plugin should retain the job-scoped IDs,
registered hooks, and writer/session objects. That is two *internal roles*, not two
competing public abstractions.

Adopt LangSmith's clear ownership boundary and `None`-versus-`False` behavior for
optional booleans. Avoid copying its raw environment access and its storing of the
API key as a normal public instance attribute: resolve Phoenix credentials through
the client utility, pass headers directly to the writer, and ensure logging/repr
never exposes them.
