An AI agent might call the wrong tool or miss a step needed to complete a user's request. Changing a prompt to fix those failures can also affect other responses, so you need to test whether your changes help.

That's where Phoenix Academy can help. You'll learn how to use tracing, evaluation, and experiments to understand agent behavior and test changes. We'll use Wonder Toys, a shopping assistant agent, to show how those changes affect quality, cost, and response time.

## Meet Wonder Toys

[Wonder Toys](https://github.com/Arize-ai/project-rosetta-stone) searches for toys, places demo orders, and checks order status. This one-minute walkthrough shows the assistant and a recorded request in Phoenix.

## Your learning path

The lessons follow the agent improvement cycle, from understanding a run to testing changes and checking behavior after release. You'll work with Wonder Toys throughout the learning path.

The learning path is organized into five stages. Each stage focuses on a different part of improving an agent:

- [Understand behavior](/docs/phoenix/learn/capture-first-run) by inspecting the steps behind a request and following a conversation.
- Find failures by reviewing traces and feedback to identify recurring problems.
- Design evaluations that check the behavior you need and give you results you can trust.
- Test a change against the same cases to see what improves and what gets worse.
- Ship and repeat by reviewing the evidence before release and checking new runs afterward.

You can follow the lessons in order or choose the stage relevant to your work. Each page explains the concepts and decisions, with links to setup and implementation details.

Start with [How teams improve an agent](/docs/phoenix/learn/improvement-loop) to see how the stages fit together.
