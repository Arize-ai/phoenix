# Phoenix Plugins for Claude Code, Codex, and Cursor

September 9 – 10, 2026

**Marketplaces added in the arize-phoenix 20.10.0 release; the plugins connect to the built-in MCP endpoint, which requires arize-phoenix 19.0.0+**

The Phoenix repository is a plugin marketplace for three coding agents. One install registers the
Phoenix MCP server against your instance — and, in Claude Code and Cursor, the Phoenix skills too —
so your agent can read traces, datasets, experiments, and prompts without hand-editing an MCP
config.

```bash
claude plugin marketplace add Arize-ai/phoenix
claude plugin install arize-phoenix@arize-phoenix
```

```bash
codex plugin marketplace add Arize-ai/phoenix
codex plugin add arize-phoenix@arize-phoenix
```

- **Claude Code and Cursor also get the skills** — `phoenix-cli`, `phoenix-evals`, and
  `phoenix-tracing` — so there is no separate `skills add` step. The Codex plugin registers the MCP
  server only.
- **Point it at your instance once.** Claude Code and Cursor prompt for a **Phoenix endpoint**
  (default `http://localhost:6006`) and append `/mcp` themselves; Codex reads `PHOENIX_ENDPOINT`
  from the shell you launch it in.
- **OAuth handles auth.** When your Phoenix requires a login, the MCP server signs in through the
  browser on first use. For a headless environment, register a bearer-token server with
  `px setup mcp` instead.
- **The plugins are optional.** The CLI, MCP server, and skills still install piece by piece for
  every agent.

# Error Analysis, Served by Phoenix

September 11 – 12, 2026

**Available in arize-phoenix 20.11.0+**

Phoenix now ships error analysis as a skill: read a sample of traces, spans, or sessions, write one
note per problem you find, then group those notes into a handful of narrow annotations — one
dimension each, with a small label set and counts — that pick eval targets and fix priorities.

- **Any MCP client can load it.** The `/mcp` handshake lists the shared skills and exposes
  `load_skill` and `load_skill_reference`, so a connected agent picks up the workflow with nothing
  installed locally.
- **PXI records what it finds.** Its MCP surface now admits the span, trace, and session note
  create routes, so open-coding notes land on the entity instead of in the chat log. The older
  `debug-trace`, `span-coding`, and `annotate-spans` skills fold into this one.
- **Wrap-up links are pre-filtered**, pointing each annotated level at its own filtered traces or
  sessions table.
- **Install it anywhere** with `npx skills add Arize-ai/phoenix --skill phoenix-error-analysis`.

# Completeness Evaluator

September 9, 2026

**Available in arize-phoenix-evals 3.7.0+ (Python) and @arizeai/phoenix-evals 2.5.0+ (TypeScript)**

Judge whether an assistant finished every active request in a conversation, not just the first one.
A run that resets the password but silently drops the billing-address change scores `incomplete`.

- **Completion means finished work** — a delivered answer, a delivered artifact including its
  required parts, or an action whose success is visible in the record. A refusal, clarifying
  question, or blocker report is not completion, and withdrawn requests are excluded.
- **Pass the whole record** as `conversation`. For agent traces, include tool calls and tool
  results so the judge can verify that an action actually succeeded.
- **One score comes back**, labeled `complete` or `incomplete`, with an explanation that walks each
  request it tracked.

```python
from phoenix.evals import LLM
from phoenix.evals.metrics import CompletenessEvaluator

evaluator = CompletenessEvaluator(llm=LLM(provider="openai", model="gpt-4o-mini"))

scores = evaluator.evaluate(
    {
        "conversation": (
            "User: Reset my password and update the billing address.\n"
            "Assistant: Your password has been reset."
        )
    }
)
print(scores[0].label)  # "incomplete"
```

```typescript
import { createCompletenessEvaluator } from "@arizeai/phoenix-evals";
import { openai } from "@ai-sdk/openai";

const evaluator = createCompletenessEvaluator({ model: openai("gpt-4o-mini") });

const result = await evaluator.evaluate({
  conversation:
    "User: Reset my password and update the billing address.\nAssistant: Your password has been reset.",
});
console.log(result.label); // "incomplete"
```

# Document Relevance Evaluators Are Deprecated

September 9, 2026

**Deprecated in arize-phoenix-evals 3.7.0 and @arizeai/phoenix-evals 2.5.0**

`DocumentRelevanceEvaluator` and `createDocumentRelevanceEvaluator` now emit a deprecation warning
and will be removed in the next major release. Retrieval relevance covers the same judgment and
accepts any retrieved context, not only a single document.

- **Rename the input field** `document_text` (`documentText` in TypeScript) to `context`.
- **The negative label changes** from `unrelated` to `irrelevant`, so update anything that branches
  on it.
- **Pass one document as `context`** to keep scoring each document separately.

```python
from phoenix.evals import LLM
from phoenix.evals.metrics import RetrievalRelevanceEvaluator

evaluator = RetrievalRelevanceEvaluator(llm=LLM(provider="openai", model="gpt-4o-mini"))

scores = evaluator.evaluate(
    {
        "input": "What is the capital of France?",
        "context": "Paris is the capital and largest city of France.",
    }
)
```

# Filter Spans by Cost, and Annotations by Identifier

September 10, 2026

**Available in arize-phoenix 20.10.0+**

The span filter now reads a span's own cost, and every filter level can match an annotation's
identifier — so "which spans burned more than a dime" and "which traces did PXI annotate" are both
one expression in the filter bar.

- **Cost scalars** `total_cost`, `prompt_cost`, and `completion_cost` read this span's cost row and
  coalesce to `0`, so a span with no recorded cost never drops out on a null.
- **`cost_details` iterates the per-token-type rows** with `any`, `all`, `len`, `sum`, `max`, and
  `min`, exposing `token_type`, `is_prompt`, `cost`, `tokens`, and `cost_per_token`.
- **`.identifier` joins `.label`, `.score`, and `.explanation`** on annotation lookups in the span,
  trace, and session filters.
- **The filter bar autocompletes the new names** and ships snippets for cost and cost-detail
  filters.

```python
total_cost > 0.10
any(cost_detail.token_type == 'cache_read' for cost_detail in cost_details)
annotations['quality'].identifier == 'pxi'
```

# Prompt Version Metadata

September 9 – 10, 2026

**Available in arize-phoenix 20.10.0+ (server and UI) and @arizeai/phoenix-client 7.11.0+ (TypeScript)**

Prompt versions carry arbitrary JSON metadata, so the owning team, an upstream dependency, or a
review flag travels with the version that needs it rather than with the prompt as a whole.

- **Set and read it over REST and GraphQL**, and pass `metadata` to the TypeScript
  `promptVersion()` helper.
- **The playground's save dialog offers the Metadata field** when saving a new version of an
  existing prompt, not only when creating a prompt.
- **The prompt version details page shows it**, so you can see what a version was tagged with
  without querying for it.

```typescript
import { createPrompt, promptVersion } from "@arizeai/phoenix-client/prompts";

await createPrompt({
  name: "support-triage",
  version: promptVersion({
    modelProvider: "OPENAI",
    modelName: "gpt-4o-mini",
    metadata: { owner: "support-eng", reviewed: true },
    template: [{ role: "user", content: "Classify this ticket: {{ticket}}" }],
  }),
});
```

# REST API Updates

September 14, 2026

**Available in arize-phoenix 20.12.0+**

- **`filter` on `GET /v1/projects/{project_identifier}/traces` and `.../sessions`** takes the same
  trace and session filter expressions the UI uses. It combines with the other query parameters
  using AND; an empty expression does not filter, and an invalid one returns `400`.
- **The discrete trace filters are deprecated.** `error`, `min_latency_ms`, and `max_latency_ms`
  still work, but `filter=error_count > 0` and `filter=latency_ms >= 1000` replace them.
- **`GET /v1/datasets/{dataset_identifier}/splits`** lists a dataset's splits with cursor
  pagination. A split appears when at least one of its examples belongs to the dataset, so
  `example_count` is dataset-scoped and agrees with the create, update, and delete endpoints.

```bash
curl -G "$PHOENIX_ENDPOINT/v1/projects/my-project/traces" \
  --data-urlencode "filter=error_count > 0 and total_cost > 0.05" \
  -H "Authorization: Bearer $PHOENIX_API_KEY"
```

# Additional Improvements

September 9 – 14, 2026

**Available in arize-phoenix 20.10.0+**

- **Reasoning gets its own block.** LLM span messages render a collapsible Reasoning section with
  the summary as markdown, and say so when the provider returned only an encrypted payload.
- **Token tooltips break out cache reads and writes**, so cumulative counts in the traces, spans,
  session, and experiment views show whether prompt caching was hit.
- **Trace and session filters live in the URL.** `traceFilterCondition` and
  `sessionFilterCondition` make a filtered table shareable, and a filtered link no longer flashes
  unfiltered rows first.
- **The traces table shows span annotations by default**, under a column name that accounts for the
  child spans expanded rows reveal.
- **Experiment comparisons open example details from an ID** and show example external IDs.
- **Notes have GraphQL mutations** for spans, traces, and sessions, with an explicit annotator kind
  and source.
- **Built-in token prices are refreshed**, image generation models stay in the cost manifest, and
  `gpt-image-2.5` is priced.
- **Annotation explanation controls are clickable and keyboard-reachable**, and code editor errors
  render inside dialogs instead of overflowing them.
- **The bundled SQLite extension driver fixes memory-safety and correctness bugs**
  (`arize-phoenix-sqlean` 0.1.2).
