`px` is how a coding agent works with Phoenix once tracing is running. It needs only a shell, so it works in every agent, and the [`phoenix-cli` skill](/docs/phoenix/integrations/developer-tools/skills) teaches the agent which commands to reach for.

Not connected yet? [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing) covers `px setup`, which wires a project to Phoenix and waits for a real trace.

## Install

```bash
# run any command without installing
npx -y @arizeai/phoenix-cli trace list

# or install once
npm install -g @arizeai/phoenix-cli
```

Point it at your instance with `PHOENIX_ENDPOINT`, plus `PHOENIX_API_KEY` if auth is on:

```bash
export PHOENIX_ENDPOINT=http://localhost:6006
```

## The debugging loop

This is the workflow the `phoenix-cli` skill drives, and the reason to hand `px` to an agent.

<Steps>
  <Step title="Find what broke">
    Pull recent traces, or filter spans down to the failures.

    ```bash
    px trace list --project my-app --limit 20
    px span list --project my-app --status-code ERROR
    ```
  </Step>

  <Step title="Read one in full">
    Fetch a single trace or span to see inputs, outputs, and timing.

    ```bash
    px trace get <trace-id> --project my-app
    px span list --project my-app --span-kind LLM --limit 5
    ```
  </Step>

  <Step title="Record what you found">
    Annotate spans and traces so the judgement is stored alongside the data.

    ```bash
    px span annotate <span-id> --name correctness --label incorrect --score 0
    px trace add-note <trace-id> --text "Tool called with an empty query"
    ```
  </Step>

  <Step title="Turn failures into a test set">
    Inspect the datasets and experiments you are testing changes against.

    ```bash
    px dataset list
    px dataset get travel-support
    px experiment list --dataset travel-support
    px experiment get <experiment-id>
    ```
  </Step>

  <Step title="Work on the prompt">
    Read the prompt a run used, and its versions.

    ```bash
    px prompt list
    px prompt get my-prompt
    ```
  </Step>
</Steps>

## Everything else

| Command | What it manages |
| --- | --- |
| `px project` | Projects |
| `px session` | Multi-turn sessions |
| `px annotation-config` | Annotation label schemas |
| `px trace-annotations`, `px span-annotations`, `px session-annotations` | Bulk deletion of stored annotations. Each takes only `delete`, and requires `--all` or a `--start-time`/`--end-time` window. |
| `px api graphql` | Read-only GraphQL queries against the Phoenix API. Mutations are rejected. |
| `px docs` | Workflow docs for coding agents |
| `px auth`, `px profile` | Credentials and saved endpoints |
| `px self` | The installed CLI |

Run `px <command> --help` for the flags on any of them.
