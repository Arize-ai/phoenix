Scalekit runs tools for an agent. See the [Scalekit docs](https://docs.scalekit.com/agentkit/connectors/). Add the setup below to an existing Scalekit app to send those tool calls to Phoenix.

## Install

```bash
npm install @scalekit-sdk/node @arizeai/phoenix-otel @arizeai/openinference-core
```

## Configure Environment

First, start Phoenix:

<StartPhoenix />

Then create a `.env` file that points your app at it:

```bash
PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006
PHOENIX_API_KEY=your-api-key # Optional, only if auth is enabled
PHOENIX_PROJECT_NAME=scalekit-agentkit
```

`PHOENIX_COLLECTOR_ENDPOINT` is the Phoenix server URL. `register()` appends `/v1/traces` when that path is missing.

The tool call also needs the Scalekit credentials from Dashboard → Developers → API credentials:

```bash
SCALEKIT_ENVIRONMENT_URL=https://your-env.scalekit.com
SCALEKIT_CLIENT_ID=your-client-id
SCALEKIT_CLIENT_SECRET=your-client-secret
```

## Setup

Register the tracer before creating any clients. `register()` from `@arizeai/phoenix-otel` reads `PHOENIX_COLLECTOR_ENDPOINT` and `PHOENIX_API_KEY` from the environment. Build the Scalekit client in the same file so it is created after tracing is active:

```typescript
// instrumentation.ts
import { register } from "@arizeai/phoenix-otel";
import { ScalekitClient } from "@scalekit-sdk/node";

export const provider = register({
  projectName: process.env.PHOENIX_PROJECT_NAME ?? "scalekit-agentkit",
});

export const scalekit = new ScalekitClient(
  process.env.SCALEKIT_ENVIRONMENT_URL!,
  process.env.SCALEKIT_CLIENT_ID!,
  process.env.SCALEKIT_CLIENT_SECRET!,
);
```

Wrap `client.actions.executeTool` with OpenInference's `traceTool` helper. It creates a `TOOL` span named after the tool and records the call arguments and result:

```typescript
// traced-tools.ts
import { traceTool } from "@arizeai/openinference-core";
import type { ScalekitClient } from "@scalekit-sdk/node";

type ExecuteToolParams = Parameters<ScalekitClient["actions"]["executeTool"]>[0];

export function createTracedToolExecutor(
  actions: Pick<ScalekitClient["actions"], "executeTool">
) {
  return (params: ExecuteToolParams) =>
    traceTool((p: ExecuteToolParams) => actions.executeTool(p), {
      name: params.toolName,
    })(params);
}
```

Then call a tool through it. `identifier` is the connected account the tool runs as:

```typescript
// example.ts
import { provider, scalekit } from "./instrumentation.js";
import { createTracedToolExecutor } from "./traced-tools.js";

const executeTool = createTracedToolExecutor(scalekit.actions);

const result = await executeTool({
  toolName: "github_issue_get",
  connector: "github-connect",
  identifier: "test-user",
  toolInput: { owner: "octocat", repo: "Hello-World", issue_number: 1 },
});
console.log(result.data);

await provider.shutdown(); // flush batched spans before the script exits
```

<Note>
Errors thrown by the SDK, such as an upstream 404 or an inactive connected account, are recorded automatically: `traceTool` marks the span `ERROR` and attaches the exception. Some connectors instead report failures inside `result.data` while resolving normally. If yours does, inspect the result and set the span status yourself. The [demo repo's `lib/traced-tools.ts`](https://github.com/scalekit-developers/arize-agentkit-tracing-demo/blob/main/lib/traced-tools.ts) shows a wrapper that does this.
</Note>

## Running Your Application

Run the example and it will call the tool once:

```bash
npx tsx example.ts
```

## Observe

Phoenix lists the turn under `PHOENIX_PROJECT_NAME`. When a model instrumentor is registered, the tool span appears beneath the active model span. A tool call that throws shows status ERROR with the exception recorded.
