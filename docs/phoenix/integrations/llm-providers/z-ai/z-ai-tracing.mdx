[Z.ai](https://z.ai/) provides GLM models through an API compatible with the OpenAI SDK. Set the OpenAI client's `base_url` to Z.ai and use [`openinference-instrumentation-openai`](https://github.com/Arize-ai/openinference/tree/main/python/instrumentation/openinference-instrumentation-openai) to send LLM traces to Phoenix.

<Note>
This page instruments OpenAI SDK calls to Z.ai's OpenAI-compatible endpoint. It is not a separate Z.ai-specific OpenInference instrumentor.
</Note>

## Install

```bash
pip install arize-phoenix-otel openinference-instrumentation-openai openai
```

## Setup

Add your Z.ai API key as an environment variable:

```bash
export ZAI_API_KEY="<your-zai-api-key>"
```

<RegisterTracerPython projectName="my-llm-app" />

## Run Z.ai

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.z.ai/api/paas/v4/",
    api_key=os.environ["ZAI_API_KEY"],
)

response = client.chat.completions.create(
    model="glm-5.3",
    messages=[
        {
            "role": "user",
            "content": "What production signal should an LLM observability tool capture?",
        },
    ],
)

print(response.choices[0].message.content)
```

## Observe

Now that you have tracing set up, all invocations of the OpenAI client pointed at Z.ai will be streamed to your running Phoenix for observability and evaluation. Each call appears as a `ChatCompletion` LLM span with the prompt, response, model name, token usage, and latency.

## Common Issues

* **Spans missing**: `register(..., auto_instrument=True)` must run before your application sends requests, and `openinference-instrumentation-openai` must be installed in the same environment
* **`401` from Z.ai**: Use your Z.ai API key, not an OpenAI key
* **Model not found**: Replace `glm-5.3` with a model available in your Z.ai account. Some Z.ai plans use a different OpenAI-compatible base URL, so confirm the endpoint in your Z.ai console
