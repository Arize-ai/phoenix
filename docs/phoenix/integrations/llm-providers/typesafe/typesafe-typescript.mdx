This module provides [OpenInference](https://github.com/Arize-ai/openinference) instrumentation for the [TypeSafe AI Node.js SDK](https://www.npmjs.com/package/@typesafe-ai/sdk) (`@typesafe-ai/sdk`). Each `TypeSafeClient.systemOne` call is captured as an OpenInference [`DECISION` span](/docs/phoenix/tracing/concepts-tracing/otel-openinference/span-kinds#decision) with JSON `input.value` / `output.value`, and with the model and token usage recorded under `decision.*`.

Requires Node.js 20+ and `@arizeai/openinference-instrumentation-typesafe >= 0.4.1`. `client.models.list()` is not instrumented.

## Install

```bash
npm install --save @arizeai/phoenix-otel @arizeai/openinference-instrumentation-typesafe @typesafe-ai/sdk
```

## Setup

Set `TYPESAFE_API_KEY` in your environment using a key from the TypeSafe console. The SDK reads this variable automatically. Use the `register` function from `@arizeai/phoenix-otel` to connect to Phoenix, then manually instrument the TypeSafe SDK for ESM.

Create the `instrumentation.ts` file:

```typescript expandable
import { register } from "@arizeai/phoenix-otel";
import { TypeSafeInstrumentation } from "@arizeai/openinference-instrumentation-typesafe";

// Initialize Phoenix tracing
export const provider = register({
  projectName: process.env.PHOENIX_PROJECT_NAME ?? "typesafe-app",
  // If Phoenix is running elsewhere:
  // url: "https://your-phoenix.example.com",
  // apiKey: process.env.PHOENIX_API_KEY,
  // If using self-hosted Phoenix:
  // url: "http://localhost:6006",
});

// Export the instrumentor so the app can patch the imported ESM module.
export const instrumentation = new TypeSafeInstrumentation({
  tracerProvider: provider,
});
```

<Note>
Because this SDK is ESM, call `manuallyInstrument()` after importing it. This patches the client method while leaving the module's exports intact.
</Note>

## Usage

```typescript expandable
import { provider, instrumentation } from "./instrumentation.js";
import * as TypeSafe from "@typesafe-ai/sdk";

instrumentation.manuallyInstrument(TypeSafe);
const { TypeSafeClient, choice } = TypeSafe;

const client = new TypeSafeClient();
const { data, requestId } = await client
  .systemOne({
    state: { document: "I was charged twice. Please fix this ASAP." },
    questions: {
      category: choice("What is this ticket about?", {
        billing: null,
        technical: null,
        other: null,
      }),
    },
  })
  .withResponse();

console.log(data.answers.category, requestId);
await provider.forceFlush();
```

<Note>
Spans are exported in batches. In short-lived scripts, call `await provider.forceFlush()` before the process exits so all spans are delivered to Phoenix.
</Note>

## Observe

With instrumentation enabled, each `systemOne` call shows up in Phoenix as a **DECISION span** containing:

- The full `state` and `questions` sent to TypeSafe as `input.value` (JSON)
- The typed `answers` returned as `output.value` (JSON)
- `decision.system` and `decision.provider`: both `typesafe`
- `decision.request.model_name`, `decision.response.model_name` (the resolved model), and `decision.model_name`
- `decision.token_count.input` and `decision.token_count.output`, when reported by the SDK

Phoenix names the decision model in the span's input card. The model and its usage follow the OpenInference [decision span conventions](https://github.com/Arize-ai/openinference/blob/main/spec/decision_spans.md) and live under `decision.*` rather than `llm.*`, so decision-model calls stay out of Phoenix's LLM token and cost reporting. Earlier releases recorded them under `llm.*`, and releases before 0.3.0 recorded them as LLM spans.


## Configuration

Pass `traceConfig` to mask sensitive request/response payloads before they leave your process:

```typescript
const instrumentation = new TypeSafeInstrumentation({
  tracerProvider: provider,
  traceConfig: {
    hideInputs: true,
    hideOutputs: true,
  },
});
```

See the [package README](https://github.com/Arize-ai/openinference/tree/main/js/packages/openinference-instrumentation-typesafe) for the full list of `traceConfig` masking options and the SDK compatibility table.
