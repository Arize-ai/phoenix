Use this series to instrument an LLM app, turn traces into a dataset, run experiments, and score outputs in Phoenix.

You will start with request-level traces, then reuse selected traces as test examples for prompt and app changes.

## **What you'll build**

By the end of this series, you will have:

- Traces that show how app requests execute
- A dataset built from traced inputs, outputs, and metadata
- Experiments that run app or prompt variants over the same examples
- Evaluator scores for comparing variants per example

That gives you a repeatable loop: inspect traces, select examples, run variants, and compare evaluator results.

## **How the guides fit together**

### **Observe your app**

Tracing shows how one app request executed.

A trace is a record of a single app request, broken down into spans that show how LLM calls, data lookups, tool calls, and other steps executed. In this guide, you instrument an app and send trace data to Phoenix.

Selected traces become dataset examples for the evaluation guide.

### **Evaluate your app**

After traces are flowing, evaluate whether outputs satisfy your criteria.

In the evaluation guide, you turn traces into a dataset, run an experiment, and score outputs with evaluators. You can use the Prompt Playground to test prompt edits in the UI, or run your app over the dataset in code.

For manual setup, start with [Observe Your App](/docs/phoenix/get-started/get-started-tracing), pick the Python or TypeScript tab, and follow the guides in order. Each step assumes the previous one is in place.
