Use this guide to turn Phoenix traces into a dataset, run an experiment, and score the outputs.

Start from traces when you want experiments to use real inputs, outputs, and failure cases from your agent. A dataset stores the examples. An experiment runs your agent or prompt over those examples. Evaluators score each result so you can compare variants.

Choose the Prompt Playground path if you want to test a saved prompt in the UI. Choose the code path if you want to run your agent over the dataset programmatically.

<Note>
  This is the second part of the Phoenix quickstart. Start with [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing) if you do not have traces flowing yet.
</Note>

## Agent-assisted evaluation

Use this path when traces are already flowing and you want a coding agent to turn them into a repeatable experiment. If you do not have traces yet, start with [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing) and run `px setup` there first.

The agent should inspect real traces, choose one behavior to measure, create or load a dataset, write a task and evaluator, run the experiment, and summarize the failures.

<Card>
  Install the Phoenix skills that let your coding agent query traces and build evaluations.

  ```bash
  npx skills add Arize-ai/phoenix --skill phoenix-cli --skill phoenix-evals
  ```

  After installation, ask your coding agent to inspect your Phoenix traces, choose one narrow behavior to measure, create or load a dataset, write a task and evaluator, run the experiment, and summarize the failures.
</Card>

## Manual evaluation

Use this path when you want to build the dataset, task, evaluator, and experiment yourself.

<Tabs>
  <Tab title="Prompt Playground">

<Steps>
  <Step title={<span className="step-title">Create a dataset from your traces</span>}>
    A dataset is a fixed set of examples you test every change against. Build one from selected traces: typical requests, edge cases, and failure cases you want future variants to handle.

    1. Navigate to your project in Phoenix.
    2. Open the **Traces** view.
    3. Select the spans you want to test against. For most agents, select the root span or the LLM span that contains the user request and final response.
    4. Click **Add to Dataset**.
    5. Pick an existing dataset, or click **+** to create one, name it, and click **Create Dataset**.

    <Frame caption="Selected spans ready to add to a dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-create-dataset-from-traces.png"
        alt="Phoenix traces table with three selected support_reply spans and the Add to Dataset action visible"
      />
    </Frame>

  </Step>

  <Step title={<span className="step-title">Attach an evaluator</span>}>
    An evaluator scores each experiment output. Attach one to the dataset and Phoenix runs it whenever you launch an experiment from the Playground.

    1. Open the dataset and click the **Evaluators** tab.
    2. Click **Add evaluator**.
    3. Choose an **LLM evaluator** for judgment-based checks, or a **built-in code evaluator** for deterministic checks.
    4. Map the evaluator inputs to your dataset fields and task output.
    5. Click **Test** on one example, then click **Create**.

    <Frame caption="Built-in evaluator configured for experiment outputs">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-attach-evaluator-config.png"
        alt="Phoenix built-in code evaluator form configured with output.text and billing-related words"
      />
    </Frame>

    <Note>
      Attached evaluators run automatically for experiments launched from the Phoenix UI. Programmatic experiments pass evaluators to `run_experiment` or `runExperiment`.
    </Note>
  </Step>

  <Step title={<span className="step-title">Save a prompt from a trace</span>}>
    Traces capture the prompts your agent sent to the model. Save one to the Prompt Hub so you can test edits against the dataset.

    1. Open a trace from the dataset.
    2. Find the LLM span you want to edit or benchmark.
    3. Open it in the Playground.
    4. Save the prompt to the Prompt Hub.

  </Step>

  <Step title={<span className="step-title">Run the prompt over the dataset</span>}>
    Running a prompt across a dataset creates an experiment. The Playground fills prompt variables from each dataset example.

    1. Navigate to the **Prompt Playground**.
    2. Select the prompt you saved.
    3. Click **Test over a dataset** and choose your dataset.
    4. Use prompt variables that match the keys inside each dataset example's `input` object. Phoenix uses `input` as the default variable path for dataset runs, so the quickstart dataset's `input.text` field becomes:

       ```text
       {{text}}
       ```

       If your examples have structured fields such as `question` and `context`, use those keys instead:

       ```text
       Question: {{question}}
       Context: {{context}}
       ```

    5. Click **Run**.

    <Frame caption="Prompt variables matched to a selected dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-run-prompt-saved-dataset.png"
        alt="Phoenix Prompt Playground with a saved support prompt selected, the text prompt variable, the Run button, evaluator controls, and the support quickstart dataset selected"
      />
    </Frame>

    That run is your baseline, scored by the evaluator you attached.

  </Step>

  <Step title={<span className="step-title">Compare changes</span>}>
    Edit the prompt, run it over the same dataset again, and compare the scores.

    1. Update the prompt in the Playground.
    2. Run it over the same dataset.
    3. Open the dataset's **Experiments** tab.
    4. Compare the baseline and edited prompt runs side by side.

    <Frame caption="Side-by-side experiment comparison">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-compare-score-delta.png"
        alt="Phoenix experiment comparison view showing a baseline support response scoring 0 and an edited response scoring 1"
      />
    </Frame>
  </Step>
</Steps>

  <Tab title="Python">

<Steps>
  <Step title={<span className="step-title">Install experiment packages</span>}>
    Install the Phoenix client package.

    ```bash
    pip install -U arize-phoenix-client
    ```
  </Step>

  <Step title={<span className="step-title">Create an experiment file</span>}>
    Create a file named `experiment.py`. The dataset uses two billing support examples; replace them with selected traces or examples from your agent when you are ready.

    ```python
    from phoenix.client import Client

    client = Client()

    dataset = client.datasets.create_dataset(
        name="support-quickstart",
        dataset_description="Support reply examples from the Phoenix quickstart.",
        examples=[
            {
                "id": "invoice-change",
                "input": {"text": "Draft a short reply about why an invoice changed."},
                "output": {
                    "text": "Explain that invoice totals can change when usage, taxes, or plan adjustments are applied."
                },
                "metadata": {"kind": "billing"},
            },
            {
                "id": "renewal-plan-change",
                "input": {
                    "text": "A customer says their renewal invoice is higher after changing plans."
                },
                "output": {
                    "text": "Explain that plan changes can cause prorated usage charges and updated taxes."
                },
                "metadata": {"kind": "billing"},
            },
        ],
    )


    def baseline_task(input):
        if "renewal" in input["text"]:
            return "Renewal amounts can change after account updates."
        return "Invoice totals can change when billing settings change."


    def edited_task(input):
        if "renewal" in input["text"]:
            return "Plan changes can create prorated usage charges and updated taxes on a renewal invoice."
        return "Invoice totals can change when usage, taxes, or plan adjustments are applied."


    def covers_billing_context(output):
        text = output.lower()
        has_usage = "usage" in text or "prorat" in text
        has_taxes = "tax" in text
        has_plan = "plan" in text
        return has_usage and has_taxes and has_plan

    client.experiments.run_experiment(
        dataset=dataset,
        task=baseline_task,
        evaluators=[covers_billing_context],
        experiment_name="support-response-baseline-docs-run",
    )

    client.experiments.run_experiment(
        dataset=dataset,
        task=edited_task,
        evaluators=[covers_billing_context],
        experiment_name="support-response-edited-docs-run",
    )
    ```

    Each task takes one dataset input and returns an agent output. Swap in your agent's entry point. The evaluator is intentionally deterministic: it checks for the billing context the response must include before you add broader LLM-as-a-judge evals.
  </Step>

  <Step title={<span className="step-title">Run the experiment</span>}>
    Run the file.

    ```bash
    python experiment.py
    ```

    If you already created a dataset from traces in the UI, replace the `create_dataset` call with:

    ```python
    dataset = client.datasets.get_dataset(dataset="<YOUR DATASET NAME>")
    ```
  </Step>

  <Step title={<span className="step-title">Review the scores</span>}>
    Head back to Phoenix and open the dataset's **Experiments** tab. You can compare outputs, evaluator labels, scores, and explanations for each example.

        alt="Phoenix experiment comparison view showing a baseline support response scoring 0 and an edited response scoring 1"
      />
    </Frame>
  </Step>

<Steps>
  <Step title={<span className="step-title">Install experiment packages</span>}>
    Install the Phoenix client package and `tsx` for running the TypeScript file.

    ```bash
    npm install @arizeai/phoenix-client tsx
    ```
  </Step>

  <Step title={<span className="step-title">Create an experiment file</span>}>
    Create a file named `experiment.ts`. The dataset uses two billing support examples; replace them with selected traces or examples from your agent when you are ready.

    ```typescript
    import { createClient } from "@arizeai/phoenix-client";
    import { createDataset } from "@arizeai/phoenix-client/datasets";
    import {
      asExperimentEvaluator,
      runExperiment,
    } from "@arizeai/phoenix-client/experiments";
    import type { Example } from "@arizeai/phoenix-client/types/datasets";

    const client = createClient();
    const datasetName = "support-quickstart";

    const baselineTask = async (example: Example): Promise<string> => {
      const input = example.input as { text: string };

      if (input.text.includes("renewal")) {
        return "Renewal amounts can change after account updates.";
      }
      return "Invoice totals can change when billing settings change.";
    };


    const editedTask = async (example: Example): Promise<string> => {
      const input = example.input as { text: string };

      if (input.text.includes("renewal")) {
        return "Plan changes can create prorated usage charges and updated taxes on a renewal invoice.";
      }
      return "Invoice totals can change when usage, taxes, or plan adjustments are applied.";
    };


    const coversBillingContext = asExperimentEvaluator({
      name: "covers_billing_context",
      kind: "CODE",
      evaluate: async ({ output }) => {
        const text = String(output).toLowerCase();
        const hasUsage = text.includes("usage") || text.includes("prorat");
        const hasTaxes = text.includes("tax");
        const hasPlan = text.includes("plan");
        const passes = hasUsage && hasTaxes && hasPlan;
        return {
          label: passes ? "True" : "False",
          score: passes ? 1 : 0,
        };
      },
    });

    async function main() {
      await createDataset({
        client,
        name: datasetName,
        description: "Support reply examples from the Phoenix quickstart.",
        examples: [
          {
            id: "invoice-change",
            input: { text: "Draft a short reply about why an invoice changed." },
            output: {
              text: "Explain that invoice totals can change when usage, taxes, or plan adjustments are applied.",
            },
            metadata: { kind: "billing" },
          },
          {
            id: "renewal-plan-change",
            input: {
              text: "A customer says their renewal invoice is higher after changing plans.",
            },
            output: {
              text: "Explain that plan changes can cause prorated usage charges and updated taxes.",
            },
            metadata: { kind: "billing" },
          },
        ],
      });

      await runExperiment({
        client,
        dataset: { datasetName },
        task: baselineTask,
        evaluators: [coversBillingContext],
        experimentName: "support-response-baseline-docs-run",
      });

      await runExperiment({
        client,
        dataset: { datasetName },
        task: editedTask,
        evaluators: [coversBillingContext],
        experimentName: "support-response-edited-docs-run",
      });
    }

    main().catch((error) => {
      console.error(error);
      process.exit(1);
    });
    ```

    Each task takes one dataset example and returns an agent output. Swap in your agent's entry point. The evaluator is intentionally deterministic: it checks for the billing context the response must include before you add broader LLM-as-a-judge evals.
  </Step>

  <Step title={<span className="step-title">Run the experiment</span>}>
    Run the file.

    ```bash
    npx tsx experiment.ts
    ```

    If you already created a dataset from traces in the UI, keep `datasetName` set to that dataset name and remove the `createDataset` call.
  </Step>

  <Step title={<span className="step-title">Review the scores</span>}>
    Head back to Phoenix and open the dataset's **Experiments** tab. You can compare outputs, evaluator labels, scores, and explanations for each example.

    <Frame caption="Side-by-side experiment comparison">

      />
    </Frame>
  </Step>
