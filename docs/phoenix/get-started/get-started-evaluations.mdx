title: "Evaluate Your Agent"
---

Evaluations in Phoenix run offline: an evaluator scores the output of an experiment. Continuous scoring of live production traffic (online evals) is in development.

Everything below runs on a dataset you paste in, so you can follow it on a fresh Phoenix with nothing instrumented yet.

## Hand it to a coding agent

Install the Phoenix skills, then paste the prompt below.

```bash
npx skills add Arize-ai/phoenix --skill phoenix-cli --skill phoenix-evals
```

```text
Download https://storage.googleapis.com/arize-phoenix-assets/assets/images/arize-docs-images/evaluate/travel-support.csv
and create a Phoenix dataset called "travel-support" from it, mapping the
question column to input and expected_answer to output.

Then write an LLM-as-a-judge evaluator that scores whether a reply answers the
question and matches the expected answer. Run an experiment over the dataset
with a travel support prompt, and tell me which examples scored lowest and why.
```

## Or ask PXI

[PXI](/docs/phoenix/pxi), the agent built into Phoenix, can run the whole flow, inventing the dataset instead of downloading it. Open it from any page, set it to Bypass Approval, and paste:

```text
Create a dataset called airline-support with 3 examples: customer questions about a fictional airline's Basic fare, with input {"question": ...} and output {"expected_answer": ...}. Invent a refund, change, and baggage policy that differs from industry norms. Then add an LLM evaluator named correctness that labels each output true or false against the expected answer, using only {{input}}, {{output}}, and {{reference}} as template variables. Run the prompt "You are a travel support agent. Answer the customer's question. Question: {{question}}" over the dataset as an experiment and tell me which examples scored lowest and why.
```

When it reports the scores, reply *Add the policy to the prompt and rerun* to see the improvement.

## Do it yourself

<Steps>
  <Step title={<span className="step-title">Start with a handful of examples</span>}>
    A dataset is a fixed set of examples you test every change against.

    1. Download [travel-support.csv](https://storage.googleapis.com/arize-phoenix-assets/assets/images/arize-docs-images/evaluate/travel-support.csv). Three questions about a fictional airline's Basic fare, with the answer each one should get.
    2. Go to **Datasets** and click **New Dataset**.
    3. Drop the file on the upload area. Phoenix accepts `.csv` and `.jsonl`.
    4. Map `question` to **input** and `expected_answer` to **output**, then create the dataset.

    The answers are specific to this airline and deliberately differ from industry norms, so a model cannot guess them. That is the point: the prompt has to supply the policy.

    <Note>
      Already have traces? Build the dataset from real failures instead. Filter the spans table with an expression such as `status_code == 'ERROR'` or `latency_ms > 1000`, or ask [PXI](/docs/phoenix/pxi) to identify traces with issues, then select those spans and click **Add to Dataset**.
    </Note>

    <Frame caption="Selected spans ready to add to a dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-create-dataset-from-traces.png"
        alt="Phoenix traces table with three selected support_reply spans and the Add to Dataset action visible"
      />
    </Frame>
  </Step>

  <Step title={<span className="step-title">Decide what good looks like</span>}>
    An evaluator turns an experiment into a measurement. Attach one to the dataset and Phoenix runs it on every experiment you launch from the Playground.

    1. Open the dataset, click the **Evaluators** tab, then **Add evaluator** and **Create new LLM evaluator**. Name it `correctness`.
    2. Replace the system message with this rubric. Leave the user message alone: it hands the judge the expected answer as `{{reference}}` and the reply as `{{output}}`.

       ```text
       Compare the provided answer to the reference answer. Label true if it states the same policy: same time windows, fees, and quantities, in any wording. Label false if it contradicts the reference, hedges, or leaves out a fee, limit, or condition.
       ```

    3. Under **Map Prompt Variables**, set `reference` to `$.reference.expected_answer`.
    4. Click **Test** on one example, then **Create**.

    The ready-made templates under **Use LLM evaluator template** judge from the question and reply alone, with no expected answer, so this guide writes its own. See [Server Evals](/docs/phoenix/evaluation/server-evals/overview) for templates and code evaluators.
  </Step>

  <Step title={<span className="step-title">Get a baseline score</span>}>
    Running a prompt across a dataset creates an experiment. Phoenix uses `input` as the default variable path, so the `question` column becomes `{{question}}`.

    1. Go to the **Prompt Playground**.
    2. Paste this as the user prompt:

       ```text
       You are a travel support agent. Answer the customer's question.

       Question: {{question}}
       ```

    3. Click **Test over a dataset** and choose `travel-support`.
    4. Click **Run**.

    That first run is your baseline. Every later edit is scored on the same dataset with the same evaluator, so the comparison isolates your change.

    <Frame caption="Prompt variables matched to a selected dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-run-prompt-saved-dataset.png"
        alt="Phoenix Prompt Playground with a saved support prompt selected, the text prompt variable, the Run button, evaluator controls, and the support quickstart dataset selected"
      />
    </Frame>
  </Step>

  <Step title={<span className="step-title">Prove the change helped</span>}>
    The baseline prompt has no way to know this airline's policy, so it answers from industry norms and gets all three wrong. Give it the policy.

    1. Replace the user prompt with this version:

       ```text
       You are a travel support agent. Answer the customer's question using this policy.

       Basic fare policy:
       - Full refund if cancelled within 48 hours of booking.
       - Can be changed once for a 40 dollar fee, plus any price difference.
       - Includes one checked bag. A second bag is 45 dollars.

       Question: {{question}}
       ```

    2. Run it over the same dataset.
    3. Open the dataset's **Experiments** tab.
    4. Compare the baseline and the edited run side by side.

    <Frame caption="Side-by-side experiment comparison">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-compare-score-delta.png"
        alt="Phoenix experiment comparison view showing a baseline support response scoring 0 and an edited response scoring 1"
      />
    </Frame>

    A higher score on the same dataset and evaluator means the edit helped. If one example still scores 0, open that run and read the judge's explanation. That is your next edit.
  </Step>
</Steps>
