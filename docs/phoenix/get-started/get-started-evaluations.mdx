title: "Evaluate Your Agent"
description: >-
  Run an experiment over a dataset and score every output with an evaluator.
---

Evaluations in Phoenix run **offline**. An evaluator scores the output of an experiment. Continuous scoring of live production traffic is not available yet.

A dataset of examples feeds a task, which is your prompt, agent, or app. The evaluator scores each output, using the example's input, its reference output, and any metadata as context.

## **Before We Start**

After completing [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing), you should have:

- Traces flowing into Phoenix

    A dataset is a fixed set of examples you test every change against. Each example holds the input your agent received, optionally a reference output to compare against, and any metadata.

    Build one from the runs you want to improve: typical interactions, edge cases, and the flagged or failed runs in your traces. See [Defining the Dataset](/docs/phoenix/datasets-and-experiments/tutorial/defining-the-dataset) for what makes a good one, or the [Create Datasets guide](https://arize.com/docs/phoenix/datasets-and-experiments/how-to-datasets/creating-datasets) to do it in code.

    ### **Create a Dataset in the UI**

    1. Navigate to your project in Phoenix.
    2. Filter the spans table to the runs you want to test against.
    3. Select the spans you want to include.
    4. Click **Add to Dataset**.
    5. Pick an existing dataset, or click **+** to create one, name it, and click **Create Dataset**.

  <Step title={<span className="step-title">Attach an Evaluator to the Dataset</span>}>
    An experiment needs an evaluator to produce a score. Attach one to the dataset and it runs on every experiment you launch from the Playground, with no code.

    1. Open the dataset and click the **Evaluators** tab.
    2. Click **Add evaluator** and choose an **LLM evaluator** to have a model judge the output, or a **built-in code evaluator** for a deterministic check such as exact match or contains.
    3. Configure the input mapping so the evaluator knows which fields to read. It can use the example's `input`, the task's `output`, the `reference` expected output, and the example's `metadata`.
    4. Click **Test** to try it against one of your examples, then click **Create**.

    See [Dataset Evaluators](/docs/phoenix/datasets-and-experiments/how-to-experiments/how-to-dataset-evaluators) for the evaluator types and [Input Mapping](/docs/phoenix/evaluation/server-evals/input-mapping) for the field paths.

    <Note>
      Attached evaluators run automatically for experiments launched from the Phoenix UI. Programmatic experiments pass their evaluators to `run_experiment` instead, which is what the **In code** tab does.
    </Note>
  </Step>

  <Step title={<span className="step-title">Save a Prompt from a Trace</span>}>
    The prompt is the task the experiment runs. Traces capture the exact prompts sent to the model, along with their context and outputs, so saving one from a trace gives you a real starting point.

    1. Navigate to your project in Phoenix.
    2. Open the Traces view and click into a trace.
    3. Find an LLM span, then open it in the Playground and save the prompt to the Prompt Hub.

  <Step title={<span className="step-title">Run the Prompt Over the Dataset</span>}>
    Running a prompt across a dataset is an experiment: each example's input becomes a task run, and the attached evaluators score each output. The playground substitutes your dataset's input keys into the prompt, using Mustache format by default, so reference them with double braces.

    1. Navigate to the **Prompt Playground**.
    2. Select the prompt you just saved from the Prompt Hub.
    3. Click **Test over a dataset** and choose the dataset you created.
    4. Set the User prompt to reference your dataset's input keys. Which keys you have depends on the agent you traced: `{{tickers}}` and `{{focus}}` if you followed the Python guide, `{{input}}` if you followed TypeScript.

       Following the Python guide, the start of the User prompt should look like this:

       ```
       Current Task:
       Research: {{tickers}}
       Focus on: {{focus}}
       ```

    5. Click **Run**.

    That run is your baseline, scored by the evaluator you attached.

    With a baseline in place, edit the prompt and run it again. The same evaluator scores both, so the comparison is like for like.

    1. Update the prompt directly in the playground. Add this line in:

       > Make sure to include more than 1 financial ratio (such as P/E or P/B).

    2. Run it to preview how outputs change.
    3. Save the new version as a separate prompt in the Prompt Hub.

    2. The **Experiments** tab lists a run for each time you ran the prompt, with its score.
    3. Open one, then use the **comparisons** selector at the top to add another and see them side by side.

    ### **Update the Agent Instructions**

    This example strengthens the agents' backstory instructions, giving the model clearer guidance on what a good response looks like.

    Below is an example of tightening the agent backstory to be more explicit about the expected output.

    ```python
    researcher = Agent(
            role="Financial Research Analyst",
            goal="""Gather up-to-date financial data, trends, and news for the target companies/markets.
            Make sure to include more than 1 financial ratios (such as P/E or P/B), news from the last 6 months, and current stock price or performance data.""",
            backstory="""
                You are a Senior Financial Research Analyst.
            """,
            verbose=True,
            allow_delegation=False,
            max_iter=2,
            tools=[search_tool],
            )

    writer = Agent(
        role="Financial Report Writer",
        goal="Compile and summarize financial research into clear, actionable insights. If there are multiple tickers, make sure to include a dedicated comparison section.",
        backstory="""
            You are an experienced financial content writer.
        """,
        verbose=True,
        allow_delegation=True,
        max_iter=1
    )
    ```

    Create an updated crew with these new, updated agents.

    ```python
    updated_crew = Crew(
    	agents=[researcher, writer],
        tasks=[task1, task2],
        verbose=True,
        process=Process.sequential,
    )
    ```

    That is a targeted change, driven by the explanations for why these traces were classified as real failures.

    ### **Define an Experiment**

    With the agent updated, run the new flow to test whether the change improves quality.

    An experiment needs two things:

    - **The experiment task**

      A task takes each example from the dataset and produces an output, usually by running your agent on the input.

    - **The experiment evaluation**

      An experiment evaluation works like any other evaluation, but scores a task's output, often against an expected result or a scoring metric.

    Here the task reruns the agent with the updated instructions. That produces new outputs for the same inputs, so rerun the same evaluation to compare the two directly.

    ```python
    def my_task(example):
        result = updated_crew.kickoff(inputs=example.input)
        return result
    ```

    ```python
    from phoenix.evals import ClassificationEvaluator

    completeness_evaluator = ClassificationEvaluator(
        name="completeness",
        prompt_template=financial_completeness_template,
        llm=llm,
        choices={"complete": 1.0, "incomplete": 0.0},
    )

    completeness_evaluator.bind(
        {
            "attributes.input.value": "input",
            "attributes.output.value": "output",
        }
    )

    evaluators = [completeness_evaluator]
    ```

    ### **Run the Experiment on the Dataset**

    Pull down the dataset you created earlier.

    That tests the new version of the agent against the exact inputs that previously failed.

    ```python
    from phoenix.client import Client

    client = Client()
    dataset = client.datasets.get_dataset(dataset="python quickstart fails")
    ```

    Then run the experiment:

    ```python
    experiment = client.experiments.run_experiment(dataset=dataset, task=my_task, evaluators=evaluators)
    ```

    Once this completes, Phoenix logs the experiment results automatically.
  </Step>

    ```typescript
    import "dotenv/config";
    import type { Example } from "@arizeai/phoenix-client/types/datasets";
    import { runExperiment } from "@arizeai/phoenix-client/experiments";
    import { createClassificationEvaluator } from "@arizeai/phoenix-evals";
    import { openai } from "@ai-sdk/openai";
    import { Agent } from "@mastra/core/agent";
    import { Mastra } from "@mastra/core/mastra";
    import { financialSearchTool } from "../tools/financial-search-tool";
    import { financialOrchestratorAgent } from "../agents/financial-orchestrator-agent";
    import { financialWriterAgent } from "../agents/financial-writer-agent";
    import { financialCompletenessTemplate } from "../evals/evals";
    ```

    Below is an example of tightening the agent instructions to be more explicit about the expected output.

    ```typescript
    const financialResearcherAgent = new Agent({
      id: "financial-researcher-agent",
      name: "Financial Research Analyst",
      instructions: `You are a Senior Financial Research Analyst. Your job is to collect accurate, up-to-date financial information so a report writer can turn it into a polished analysis.

    What to do:
    - Use the financialSearch tool to look up each company or ticker mentioned in the request.
    - For every ticker, pull: current or recent prices, key ratios (P/E, P/B, debt-to-equity, ROE), revenue and earnings, and notable news or events from the last 6 months.
    - If the user asks for a specific focus (e.g. valuation, growth, dividends), prioritize that in your search and summary.
    - For multiple tickers, run research per ticker and then summarize in one coherent research brief.

    Output:
    - Produce a single research summary that covers all requested tickers and focus areas.
    - Be specific: use numbers and sources, not vague statements.
    - Write so the Financial Report Writer can use this summary directly to draft the final report.

    Make sure to report financial data for all tickers mentioned in the request. Use that financial data for the specific focus area mentioned in the request.`,
      model: "openai/gpt-4o",
      tools: { financialSearchTool },
    });
    ```

    Create an updated Mastra instance with this new, modified agent:

    ```typescript
    async function main() {
      const mastra = new Mastra({
        agents: {
          financialResearcherAgent,
          financialWriterAgent,
          financialOrchestratorAgent,
        },
      });
    ```

    ### **Define an Experiment**

    With the agent updated, run the new flow to test whether the change improves quality.

    An experiment needs two things:

    - **The experiment task**

      A task takes each example from the dataset and produces an output, usually by running your agent on the input.

    - **The experiment evaluation**

      An experiment evaluation works like any other evaluation, but scores a task's output, often against an expected result or a scoring metric.

    Here the task reruns the agent with the updated instructions. That produces new outputs for the same inputs, so rerun the same evaluation to compare the two directly.

    #### **Define the Task**

    ```typescript
      const task = async (example: Example): Promise<string> => {
        const raw = example.input as unknown as
          | { role: "user"; content: string }[]
          | { input: { role: "user"; content: string }[] };
        const messages = Array.isArray(raw) ? raw : raw.input;
        const response = await mastra
          .getAgent("financialOrchestratorAgent")
          .generate(messages);
        return response.text ?? "";
      };
    ```

    #### **Define the Evaluator**

    ```typescript
      const completenessEvaluator = createClassificationEvaluator({
        model: openai("gpt-4o-mini"),
        promptTemplate: financialCompletenessTemplate,
        choices: { complete: 1, incomplete: 0 },
        name: "completeness",
      });
    ```

    ### **Run the Experiment on the Dataset**

    Specify the dataset you created earlier.

    That tests the new version of the agent against the exact inputs that previously failed.

    ```typescript
      const datasetSelector = { datasetName: "ts quickstart fails" };

      await runExperiment({
        dataset: datasetSelector,
        task,
        evaluators: [completenessEvaluator],
        experimentName: "new-experiment",
      });
    }
    ```

## **Learn More**

[Datasets and Experiments](https://arize.com/docs/phoenix/datasets-and-experiments/overview-datasets) covers building datasets for specific user segments or edge cases, comparing multiple prompt or model variants, and tracking quality over time.

For evaluators themselves, [Server Evals](/docs/phoenix/evaluation/server-evals/overview) covers the LLM and built-in code evaluators you can attach to a dataset, and the [Evaluation](/docs/phoenix/evaluation/evals) section covers writing your own.

The [Prompt Playground and Prompt Hub guides](https://arize.com/docs/phoenix/prompt-engineering/tutorial) go deeper on prompt iteration and versioning.

To score traces you have already collected rather than an experiment, see [Evaluating Phoenix Traces](/docs/phoenix/tracing/how-to-tracing/feedback-and-annotations/evaluating-phoenix-traces), which runs an evaluator over spans and logs the results back as annotations. The [Python](/docs/phoenix/evaluation/python-quickstart) and [TypeScript](/docs/phoenix/evaluation/typescript-quickstart) eval quickstarts cover the same flow in code.
