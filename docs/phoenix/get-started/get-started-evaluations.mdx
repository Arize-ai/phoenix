Use this guide to turn Phoenix traces into a dataset, run an experiment, and score the outputs.

Start from traces when you want experiments to use real inputs, outputs, and failure cases from your agent. A dataset stores the examples. An experiment runs your agent or prompt over those examples. Evaluators score each result so you can compare variants.

Choose the Prompt Playground path if you want to test a saved prompt in the UI. Choose the code path if you want to run your agent over the dataset programmatically.

<Note>
  This is the second part of the Phoenix quickstart. Start with [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing) if you do not have traces flowing yet.
</Note>

## Agent-assisted evaluation

Use this path when traces are already flowing and you want a coding agent to turn them into a repeatable experiment. If you do not have traces yet, start with [Observe Your Agent](/docs/phoenix/get-started/get-started-tracing) and run `px setup` there first.

The agent should inspect real traces, choose one behavior to measure, create or load a dataset, write a task and evaluator, run the experiment, and summarize the failures.

<Card>
  Install the Phoenix skills that let your coding agent query traces and build evaluations.

  ```bash
  npx skills add Arize-ai/phoenix --skill phoenix-cli --skill phoenix-evals
  ```

  After installation, ask your coding agent to inspect your Phoenix traces, choose one narrow behavior to measure, create or load a dataset, write a task and evaluator, run the experiment, and summarize the failures.
</Card>

## Manual evaluation

Use this path when you want to build the dataset, task, evaluator, and experiment yourself.

<Steps>
  <Step title={<span className="step-title">Create a dataset from your traces</span>}>
    A dataset is a fixed set of examples you test every change against. Ten to twenty is enough to start: a few typical requests plus the failures you want future variants to handle.

    To find the failures, filter the spans table with a [filter expression](/docs/phoenix/tracing/how-to-tracing/filter-expressions) such as `status_code == 'ERROR'` or `latency_ms > 1000`, or ask [PXI](/docs/phoenix/pxi) to walk your failing traces and propose root causes.

    1. Navigate to your project in Phoenix.
    2. Open the **Traces** view.
    3. Select the spans you want to test against. For most agents, select the root span or the LLM span that contains the user request and final response.
    4. Click **Add to Dataset**.
    5. Pick an existing dataset, or click **+** to create one, name it, and click **Create Dataset**.

    <Frame caption="Selected spans ready to add to a dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-create-dataset-from-traces.png"
        alt="Phoenix traces table with three selected support_reply spans and the Add to Dataset action visible"
      />
    </Frame>

  </Step>

  <Step title={<span className="step-title">Attach an evaluator</span>}>
    An evaluator scores each experiment output. Attach one to the dataset and Phoenix runs it whenever you launch an experiment from the Playground.

    Score one error pattern you have already seen in your traces: an incomplete answer, a tool called with bad arguments, a refusal, or a response that ignores the retrieved context. One narrow question gives a clearer signal than a general quality rating.

    1. Open the dataset and click the **Evaluators** tab.
    2. Click **Add evaluator**.
    3. Choose an **LLM evaluator** for judgment-based checks, or a **built-in code evaluator** for deterministic checks.
    4. Map the evaluator inputs to your dataset fields and task output.
    5. Click **Test** on one example, then click **Create**.

    <Frame caption="Built-in evaluator configured for experiment outputs">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-attach-evaluator-config.png"
        alt="Phoenix built-in code evaluator form configured with output.text and billing-related words"
      />
    </Frame>

    <Note>
      Attached evaluators run automatically for experiments launched from the Phoenix UI. Programmatic experiments pass evaluators to `run_experiment` or `runExperiment`.
    </Note>
  </Step>

  <Step title={<span className="step-title">Save a prompt from a trace</span>}>
    An experiment needs something to run over the dataset. Traces capture the prompts your agent sent to the model, so saving one gives you the exact prompt running in production today. That becomes the version every later edit is measured against.

    1. Open a trace from the dataset.
    2. Find the LLM span you want to edit or benchmark.
    3. Open it in the Playground.
    4. Save the prompt to the Prompt Hub.

  </Step>

  <Step title={<span className="step-title">Run the prompt over the dataset</span>}>
    Running a prompt across a dataset creates an experiment. The Playground fills prompt variables from each dataset example.

    1. Navigate to the **Prompt Playground**.
    2. Select the prompt you saved.
    3. Click **Test over a dataset** and choose your dataset.
    4. Use prompt variables that match the keys inside each dataset example's `input` object. Phoenix uses `input` as the default variable path for dataset runs, so the quickstart dataset's `input.text` field becomes:

       ```text
       {{text}}
       ```

       If your examples have structured fields such as `question` and `context`, use those keys instead:

       ```text
       Question: {{question}}
       Context: {{context}}
       ```

    5. Click **Run**.

    <Frame caption="Prompt variables matched to a selected dataset">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-run-prompt-saved-dataset.png"
        alt="Phoenix Prompt Playground with a saved support prompt selected, the text prompt variable, the Run button, evaluator controls, and the support quickstart dataset selected"
      />
    </Frame>

    That first run is your baseline. Every later edit is scored on the same dataset with the same evaluator, so the comparison isolates your change.

  </Step>

  <Step title={<span className="step-title">Compare changes</span>}>
    Edit the prompt, run it over the same dataset again, and compare the scores.

    1. Update the prompt in the Playground.
    2. Run it over the same dataset.
    3. Open the dataset's **Experiments** tab.
    4. Compare the baseline and edited prompt runs side by side.

    <Frame caption="Side-by-side experiment comparison">
      <img
        src="https://storage.googleapis.com/arize-phoenix-assets/assets/images/get-started/evaluations-compare-score-delta.png"
        alt="Phoenix experiment comparison view showing a baseline support response scoring 0 and an edited response scoring 1"
      />
    </Frame>

    A higher score on the same dataset and evaluator means the edit helped. If the score drops, open a failing run and read the evaluator's explanation before your next edit.
  </Step>
</Steps>

## Prefer to do this in code?

The steps above use the Prompt Playground, so there is nothing to install and no code to write. To build the dataset, task, evaluator, and experiment programmatically, see [Run Experiments](/docs/phoenix/datasets-and-experiments/how-to-experiments/run-experiments) for the same flow with the Python SDK, or the [TypeScript experiments reference](/docs/phoenix/sdk-api-reference/typescript/packages/phoenix-client/experiments) for `runExperiment`.
