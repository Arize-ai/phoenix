This page walks through the steps for sending your first trace to Phoenix. Need to learn more about tracing first? [What are traces](/docs/phoenix/tracing/concepts-tracing/what-are-traces) explains spans and attributes, and [How tracing works](/docs/phoenix/tracing/concepts-tracing/how-tracing-works) explains what happens between your app and Phoenix.

Phoenix is the open source product offered by Arize. Run it locally from your terminal, inside a notebook, or [self-hosted](/docs/phoenix/self-hosting) on your own infrastructure. The instrumentation stays the same whichever you pick, and only `PHOENIX_COLLECTOR_ENDPOINT` changes.

## Agent-assisted setup (Recommended)

<Card>
  <Tabs>
    <Tab title="Run px setup">
      Start Phoenix, or point at an existing deployment.

      ```bash
      uvx arize-phoenix serve
      ```

      Then, from your project root:

      ```bash
      npx -y @arizeai/phoenix-cli setup
      ```

      Follow the prompts. It asks for a project name and API key if needed, writes `.env.phoenix`, hands instrumentation to your coding agent, and finishes when a real trace arrives. Then open your project's **Traces** tab.

      See the [Phoenix CLI](/docs/phoenix/integrations/developer-tools/cli) page for a global install, supported agents, and CI flags.
    </Tab>

    <Tab title="Ask your coding agent">
      For an agent `px setup` does not support, install the Phoenix skills and ask it yourself.

      ```bash
      npx -y @arizeai/phoenix-cli setup skills
      ```

      Start Phoenix, then paste the prompt below from your project root.

      ```bash
      uvx arize-phoenix serve
      ```

      ```text
      Use the Phoenix tracing skill to instrument this application.

      First inspect the codebase and identify the LLM providers, frameworks,
      package manager, and existing OpenTelemetry setup. Then propose the
      Phoenix instrumentation plan before changing code.
      ```

      If your agent cannot install skills, use the [Phoenix tracing setup prompt](https://raw.githubusercontent.com/Arize-ai/phoenix/main/docs/PROMPT.md) instead.
    </Tab>
  </Tabs>
</Card>

## Manual setup

Use this path when you want to add the tracing code yourself.

<Steps>
  <Step title={<span className="step-title">Start Phoenix</span>}>
    Phoenix has to be running before anything can send traces to it. It ships as a Python package, so `uvx` is the quickest local option even if your agent is TypeScript.

    <StartPhoenix />
  </Step>

  <Step title={<span className="step-title">Get your keys</span>}>
    The example below calls OpenAI, so you need an [OpenAI API key](https://platform.openai.com/api-keys).

    <PhoenixAuthNote />
  </Step>

  <Step title={<span className="step-title">Set up tracing</span>}>
    <Tabs>
      <Tab title="Python">
    Install Phoenix's tracing helper, OpenAI, and the OpenInference OpenAI instrumentor. The tracing packages need Python 3.10 or later; on an older Python, `pip` installs outdated versions without warning.

    ```bash
    pip install -U arize-phoenix-otel openai openinference-instrumentation-openai
    ```

    Create a file named `quickstart.py`. Set your OpenAI key and point tracing at your local Phoenix instance.

    ```python
    import os

    os.environ["OPENAI_API_KEY"] = "<ENTER YOUR OPENAI API KEY>"
    os.environ["PHOENIX_COLLECTOR_ENDPOINT"] = "http://localhost:6006"
    ```

    Register a Phoenix tracer provider and instrument OpenAI.

    ```python
    from openai import OpenAI
    from openinference.instrumentation.openai import OpenAIInstrumentor
    from phoenix.otel import register

    tracer_provider = register(
        project_name="tracing-quickstart",
        protocol="http/protobuf",
    )
    tracer = tracer_provider.get_tracer(__name__)
    OpenAIInstrumentor().instrument(tracer_provider=tracer_provider)

    client = OpenAI()
    ```

    After this registration, OpenAI calls are exported to Phoenix as traces.
      </Tab>

      <Tab title="TypeScript">
    Install OpenAI, Phoenix's TypeScript tracing helper, and the OpenInference OpenAI instrumentor.

    ```bash
    npm install openai @arizeai/phoenix-otel @arizeai/openinference-instrumentation-openai dotenv tsx
    ```

    Add these environment variables to `.env`.

    ```bash
    OPENAI_API_KEY=<ENTER YOUR OPENAI API KEY>

    PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006
    PHOENIX_PROJECT=tracing-quickstart
    ```

    Create an instrumentation file named `instrumentation.ts`, and import it before your agent makes OpenAI calls.

    ```typescript
    import "dotenv/config";

    import OpenAI from "openai";
    import { OpenAIInstrumentation } from "@arizeai/openinference-instrumentation-openai";
    import { register, registerInstrumentations } from "@arizeai/phoenix-otel";

    export const provider = register({
      projectName:
        process.env.PHOENIX_PROJECT ??
        process.env.PHOENIX_PROJECT_NAME ??
        "tracing-quickstart",
      url: process.env.PHOENIX_COLLECTOR_ENDPOINT ?? "http://localhost:6006",
      apiKey: process.env.PHOENIX_API_KEY,
    });

    const instrumentation = new OpenAIInstrumentation();
    instrumentation.manuallyInstrument(OpenAI);

    registerInstrumentations({
      instrumentations: [instrumentation],
    });
    ```

    After this registration, OpenAI calls are exported to Phoenix as traces.
      </Tab>
    </Tabs>
  </Step>

  <Step title={<span className="step-title">Generate some traces</span>}>
    <Tabs>
      <Tab title="Python">
    Add a small support-assistant function, then send representative requests through it.

    ```python
    @tracer.chain(name="support_reply")
    def run_my_app(user_input: str) -> str:
        response = client.chat.completions.create(
            model="gpt-5-mini",
            messages=[
                {
                    "role": "system",
                    "content": "You are a concise support assistant. Ask one clarifying question when needed.",
                },
                {"role": "user", "content": user_input},
            ],
        )
        return response.choices[0].message.content or ""

    inputs = [
        "Draft a short reply about why an invoice changed.",
        "A customer says an upload failed twice. Ask one question before troubleshooting.",
        "Write a reply for a customer asking about a delayed refund.",
        "Help a user who cannot reset their password.",
        "Ask one question to debug a dashboard that suddenly became slow.",
    ]

    for user_input in inputs:
        print(run_my_app(user_input))

    tracer_provider.force_flush()
    ```

    Run the file.

    ```bash
    python quickstart.py
    ```

    Replace the support assistant with your agent's entry point when you are ready. Include typical requests plus edge cases so Phoenix captures both normal behavior and failure-prone paths.
      </Tab>

      <Tab title="TypeScript">
    Create a file named `app.ts`, add a small support-assistant function, then send representative requests through it.

    ```typescript
    import OpenAI from "openai";
    import { traceChain } from "@arizeai/phoenix-otel";
    import { provider } from "./instrumentation";

    const client = new OpenAI();

    const runMyApp = traceChain(
      async (userInput: string): Promise<string> => {
        const response = await client.chat.completions.create({
          model: "gpt-5-mini",
          messages: [
            {
              role: "system",
              content:
                "You are a concise support assistant. Ask one clarifying question when needed.",
            },
            { role: "user", content: userInput },
          ],
        });
        return response.choices[0]?.message?.content ?? "";
      },
      { name: "support_reply" }
    );

    const inputs = [
      "Draft a short reply about why an invoice changed.",
      "A customer says an upload failed twice. Ask one question before troubleshooting.",
      "Write a reply for a customer asking about a delayed refund.",
      "Help a user who cannot reset their password.",
      "Ask one question to debug a dashboard that suddenly became slow.",
    ];

    async function main() {
      for (const userInput of inputs) {
        console.log(await runMyApp(userInput));
      }

      await provider.shutdown();
    }

    main().catch(async (error) => {
      console.error(error);
      await provider.shutdown();
      process.exit(1);
    });
    ```

    Run the file.

    ```bash
    npx tsx app.ts
    ```

    Replace the support assistant with your agent's entry point when you are ready. Include typical requests plus edge cases so Phoenix captures both normal behavior and failure-prone paths.
      </Tab>
    </Tabs>
  </Step>

  <Step title={<span className="step-title">Look at the trace in Phoenix</span>}>
    Once the runs complete, head back to Phoenix, open your project, and select the **Traces** tab. You should see one trace per request. Click into a trace to inspect the spans, prompts, responses, timing, and errors.

    </Frame>
  </Step>
</Steps>

## Learn more about traces

Other ways to read your traces:

- **In code**, with [Extract data from spans](/docs/phoenix/tracing/how-to-tracing/importing-and-exporting-traces/extract-data-from-spans).
- **From a coding agent**, with the [CLI](/docs/phoenix/integrations/developer-tools/cli) or [MCP](/docs/phoenix/integrations/mcp).
- **By asking [PXI](/docs/phoenix/pxi)**, for example *"why did this trace fail?"*
- **Across multi-turn conversations**, with [Sessions](/docs/phoenix/tracing/llm-traces/sessions).

To go deeper on tracing, the [Tracing Tutorial](/docs/phoenix/tracing/tutorial) covers how to read spans, understand timing, and use trace data to debug and analyze your agent.
