title: "Improve your agent"

A prompt is the set of instructions and context sent to the model to produce an output. An experiment is a structured comparison between versions of your agent using the same inputs and evaluation criteria.

In this guide, you'll group failing runs into a dataset, change your agent to address what your evaluations flagged, then rerun that dataset and compare the results side by side.

Make the change in the Prompt Playground without writing code, or in your own code. Both paths end in the same experiment comparison.

## **Before We Start**

After completing previous guides, you should have:

- Traces flowing into Phoenix
- At least one evaluation defined and logged

  <Step title={<span className="step-title">Create a Dataset from Failed Traces</span>}>
    Start by grouping together the traces that didn’t perform well.

    A dataset collects a specific set of traces so you can analyze them together and reuse them later for testing. Build one from the traces that received an **incomplete** evaluation label, and you have a fixed set of failures to test every future change against.

    Datasets can be created in code, but this walkthrough uses the Phoenix UI. To do it programmatically, see the [Create Datasets guide](https://arize.com/docs/phoenix/datasets-and-experiments/how-to-datasets/creating-datasets).

    ### **Create a Dataset in the UI**

    1. Navigate to your project in Phoenix.
    2. Filter your traces by the incomplete evaluation label.

       `evals['completeness'].label == 'incomplete'`

    3. Select the traces you want to include.
    4. Click Create Dataset and give it a name.
    5. Add the selected traces to the dataset you just created.

    This dataset now represents a concrete failure case for your agent.

    The dataset groups the failures. Now decide which issue to fix.

    The explanations your evals produced, read alongside the trace context, tell you why these runs failed. Look through the traces in this dataset for patterns: unclear instructions, missing constraints, or outputs that don’t follow the expected structure.

    Open the trace view for a failed run and click into a trace. The annotations column holds the evaluation’s explanation for labeling that answer "incomplete".

    ### **Define an Experiment**

    With the agent updated, run the new flow to test whether the change improves quality.

    An experiment reruns the same inputs through different versions of your agent and compares the results side by side, so improvements are measured rather than assumed.

    To define an experiment, we need to specify:

    - **The experiment task**

      A task is a function or process that takes each example from a dataset and produces an output, typically by running your agent logic or model on the input.

    - **The experiment evaluation**

      An experiment evaluation is essentially the same as a regular evaluation, but specifically assesses the quality of a task's output, often by comparing it to an expected result or applying a scoring metric.

    Here the task reruns the agent with the updated instructions. That produces new outputs for the same inputs, so rerun the same evaluation to compare the two directly.

    <Tabs>
    <Tab title="Python">
    ```python
    def my_task(example):
        result = updated_crew.kickoff(inputs=example.input)
        return result
    ```

    ```python
    from phoenix.evals import ClassificationEvaluator

    completeness_evaluator = ClassificationEvaluator(
        name="completeness",
        prompt_template=financial_completeness_template,
        llm=llm,
        choices={"complete": 1.0, "incomplete": 0.0},
    )

    completeness_evaluator.bind(
        {
            "attributes.input.value": "input",
            "attributes.output.value": "output",
        }
    )

    evaluators = [completeness_evaluator]
    ```
    </Tab>
    <Tab title="TypeScript">
    #### **Define the Task**

    ```typescript
      const task = async (example: Example): Promise<string> => {
        const raw = example.input as unknown as
          | { role: "user"; content: string }[]
          | { input: { role: "user"; content: string }[] };
        const messages = Array.isArray(raw) ? raw : raw.input;
        const response = await mastra
          .getAgent("financialOrchestratorAgent")
          .generate(messages);
        return response.text ?? "";
      };
    ```

    #### **Define the Evaluator**

    ```typescript
      const completenessEvaluator = createClassificationEvaluator({
        model: openai("gpt-4o-mini"),
        promptTemplate: financialCompletenessTemplate,
        choices: { complete: 1, incomplete: 0 },
        name: "completeness",
      });
    ```

## **Learn More About Prompts and Experiments**

You can use the Prompt Playground to test prompt changes across different datasets, compare prompt variants, and see how small changes affect outputs at scale. Saving prompts to the Prompt Hub helps keep track of versions and reuse prompts across experiments. The [Prompt Playground and Prompt Hub guides](https://arize.com/docs/phoenix/prompt-engineering/tutorial) go deeper into these workflows and show how to apply them as your agent evolves.

This was a simple example, but datasets and experiments support much more advanced workflows. To go deeper, you can build datasets for specific user segments or edge cases, compare multiple prompt or model variants, and track quality improvements over time as your agent evolves. The [Datasets and Experiments](https://arize.com/docs/phoenix/datasets-and-experiments/overview-datasets) section covers these patterns in more detail.
