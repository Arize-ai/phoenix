**PXI** (pronounced *"pixie"*, short for **Phoenix Intelligence**) is a coding agent pointed at your observability data instead of a codebase. It reads the page you are already on, so you hand it the investigation rather than clicking through traces, prompts, and experiments yourself.

## What it does

- **Investigates failures**: walks failing traces and proposes root causes.
- **Iterates on prompts**: reads, edits, and tests playground prompts, with every change shown as a diff you approve.
- **Reasons over your data**: queries your Phoenix instance to answer questions evals and dashboards cannot.
- **Drives the product**: navigates, filters, and pivots through your Phoenix data the way you would.

## Get started

<Steps>
  <Step title="Configure a model">
    Set credentials for at least one provider: OpenAI, Anthropic, Gemini, AWS Bedrock, or a custom provider under **Settings → Models**. PXI defaults to an Anthropic model, so pick a model that matches the provider you configured. See [supported models](/docs/phoenix/pxi-learn-more#models).
  </Step>
  <Step title="Open it">
    Click the assistant button on any Phoenix page, or press <kbd>⌘I</kbd> (<kbd>Ctrl+I</kbd> on Windows and Linux). Accept the consent gate the first time.
  </Step>
  <Step title="Ask it something">
    From a failing trace, try *"why did this fail?"* From the prompt playground, try *"make this prompt more robust to empty input."* No need to paste IDs or copy data.
  </Step>
</Steps>
