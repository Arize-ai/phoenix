In [Capture your first agent run](/docs/phoenix/learn/capture-first-run), you enabled auto instrumentation to record model and tool calls. Now you'll add a span of your own so you can choose which work it covers and what it records.

This is [manual instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/instrument#2-as-a-with-clause-to-trace-specific-code-blocks). We'll use an **agent span** to keep a complete request, its result, and the calls behind it together, making the interaction easier to review and evaluate.

We'll practice in the app you're already running by adding a **Wonder Toys** span above LangGraph's existing steps.

## Before you start

To follow the exercise, continue with your setup from the previous lesson:

- Keep the same Phoenix instance running.
- Work in the same `no-observability/langchain-py` folder.
- Use the `_tracer_provider` you created in `backend/tracing.py`.

## Step 1: Add the agent span

Before adding a span, decide:

- **What to trace:** The work you want to review together. Here, that's one complete agent request.
- **What to record:** The user's request as input and the complete result as output.
- **When to finish:** After the agent's work is complete, including any streamed reply.

We'll use a [**context manager**](/docs/phoenix/tracing/how-to-tracing/setup-tracing/instrument#2-as-a-with-clause-to-trace-specific-code-blocks), a `with` block, to mark where that work starts and ends. Calls recorded while this span is active appear underneath it.

In our practice app, the reply arrives in pieces, so we'll collect the text before recording the output. The short example below shows the tracing code used in the full function:

```python title="Tracing pattern used in this lesson" wrap
with _tracer.start_as_current_span(
    "Wonder Toys", openinference_span_kind="agent"
) as root_span:
    root_span.set_input(question)
    # Run the agent here and append its reply to response_parts.
    root_span.set_output("".join(response_parts))
```

Here, `question` holds the user's latest message and `response_parts` holds the streamed text. In the full function, `agent.astream_events(...)` runs inside the block, so its automatically recorded **LangGraph** span appears beneath our new span.

        In the same file, replace the existing `stream_agent` function with the complete function below. It keeps the chat's streaming code and adds the span around it. The highlighted lines record the request and streamed reply.

        <Accordion title="Copy the complete stream_agent function">

    ```python title="stream_agent" highlight={15,16,17,18,44,48,54,55}
    async def stream_agent(messages: list[dict], user_id: str) -> AsyncIterator[str]:
        agent = get_agent()
        lc_messages = _lc_messages(messages, user_id)

        had_text_before = False
        in_tool_call = False

        question = next(
            (message.get("content", "") for message in reversed(messages)
             if message.get("role") == "user"),
            "",
        )
        response_parts = []

        with _tracer.start_as_current_span(
            "Wonder Toys", openinference_span_kind="agent"
        ) as root_span:
            root_span.set_input(question)
            async for event in agent.astream_events(
                {"messages": lc_messages},
                version="v2",
                config={"recursion_limit": 25},
            ):
                kind = event["event"]

                if kind == "on_chat_model_stream":
                    chunk = event["data"]["chunk"]
                    # Check for tool call chunks
                    if hasattr(chunk, "tool_call_chunks") and chunk.tool_call_chunks:
                        in_tool_call = True
                        continue

                    # Check for text content
                    text = ""
                    if isinstance(chunk.content, str):
                        text = chunk.content
                    elif isinstance(chunk.content, list):
                        for block in chunk.content:
                            if isinstance(block, dict) and block.get("type") == "text":
                                text += block.get("text", "")

                    if text:
                        if in_tool_call and had_text_before:
                            response_parts.append("\n\n")
                            yield f"data: {json.dumps({'text': chr(10) + chr(10)})}\n\n"
                        in_tool_call = False
                        had_text_before = True
                        response_parts.append(text)
                        yield f"data: {json.dumps({'text': text})}\n\n"

                elif kind == "on_tool_start":
                    in_tool_call = True

            root_span.set_output("".join(response_parts))
            root_span.set_status(StatusCode.OK)

        yield "data: [DONE]\n\n"
    ```

## Step 2: Send a request

Let's send a request to check that the span records the work and result we intended.

- **Restart the app.** Stop it in its terminal, then run this from `no-observability/langchain-py` to load your changes:

  ```bash
  UV_PYTHON=3.11 npm run dev
  ```

- **Send a request.** When the app is ready, you'll see its address next to **Local** in your terminal. Open that address in your browser and send:

  ```text wrap
  Find dinosaur toys for a 6-year-old under $25. Recommend at most 3 options.
  ```

Wait for the reply to finish, then return to Phoenix.

## Step 3: Inspect the result

Your new trace should now have a **Wonder Toys** span above **LangGraph**. In Phoenix:

- Open **wonder-toys → Traces** and select the latest **Wonder Toys** request.
- Select the **Wonder Toys** span. Its kind should be **AGENT** and its status **OK** after the reply finishes.
- Under **Info**, compare **Input** with the shopper's message and **Output** with the answer in the chat.
- Expand the tree to find the model and tool spans underneath it.
