Teams improve agents by learning from real requests and testing changes against clear expectations. The agent improvement cycle organizes that work into five connected stages. This page explains the purpose of each stage before the following lessons put them into practice.

## Why teams need this process

This example shows a requirement the agent missed. To address it, a team needs to understand what happened and test whether a change improves similar requests. The agent improvement cycle connects those activities.

## The agent improvement cycle

Each of the five stages has a different purpose, from understanding current behavior to checking a change after release. Teams can revisit earlier stages as they learn more.

  <img className="hidden dark:block" src="/docs/phoenix/learn/images/academy-loop-dark.svg" alt="Five stages in a repeating cycle: understand behavior, find failures, design evaluations, test a change, ship and repeat" />

### Understand behavior

Tracing records the steps behind a response, including model calls, retrieval, and tool use. That record helps a team understand how the agent reached its result.

### Find failures

Reviewing those traces and user feedback reveals where the agent falls short. Patterns across requests help the team choose which problems to address.

### Design evaluations

Evaluations turn requirements into checks that can be applied consistently. Test cases capture the situations the agent needs to handle, including previously observed failures.

### Test a change

Experiments compare agent versions using the same test cases and evaluations. The results show which behaviors improved, which got worse, and how cost or response time changed.

### Ship and repeat

The comparison informs whether a change is ready to release. New requests then reveal issues that become test cases for future changes.
