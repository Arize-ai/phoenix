Sessions appear when related traces share the same non-empty `session.id`. Use them to review one conversation or user journey in order.

## How Phoenix tracks sessions

Phoenix creates or updates a session when it receives a trace with `session.id`. Each trace is usually one turn or request in the conversation.

To create a session, tag related spans with the same `session.id`. Add `user.id` when you want Phoenix to show the user for the session.

<Tip>
If you do not see sessions, check that your app sends `session.id` before the traced work runs.
</Tip>

## What sessions show

The Sessions table shows the session ID, first input, last output, user ID, annotation summaries, start time, end time, p50 and p99 trace latency, total tokens, total cost, and total trace count.

Open a session to review its traces and turns in order. Use session filters when you need conversations with errors, high cost, many turns, or poor session-level feedback.
