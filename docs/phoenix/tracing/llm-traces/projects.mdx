Projects group related traces, sessions, and annotations. Use one project for each app, environment, evaluation run, or workflow that you want to review separately.

With projects, you can:

* Separate production, staging, and development traces

* Keep different applications or workflows apart

* Review evaluation runs without mixing them with app traffic

* Give teams a shared place to inspect the same trace data

Project Settings lets you add a **description**, choose **gradient colors**, set the **default project tab**, and assign a **data retention policy**. The page also shows an **annotation summary** and lets an admin bulk-delete annotations by name.

Projects also help when you compare changes. For example, you can send two versions of an application to separate projects, then review trace quality, latency, cost, and annotation scores side by side.

## Annotation summary and bulk delete

The Project Settings tab includes an **annotation summary** that lists each annotation name in the project. The summary shows how many span, trace, and session annotations use each name.

From the same summary, an admin can **bulk-delete every annotation with a given name** across the project. You can also scope the delete to a **time range** so Phoenix removes only annotations created within that window.

<Warning>
Bulk deletion is **destructive and cannot be undone**. When authentication is enabled, only admins can bulk-delete annotations. To remove one annotation instead, use the per-row delete action in the table view under the `Annotations` tab.
</Warning>

## Jump to any resource with the command palette

Press **⌘K** (macOS) or **Ctrl+K** (Windows/Linux) anywhere in Phoenix to open the global command palette. Start typing to search across your projects, datasets, experiments, and prompts. You can jump to top-level pages or reopen something you recently viewed.
