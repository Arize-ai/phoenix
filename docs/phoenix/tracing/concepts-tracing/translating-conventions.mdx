Use this page when your application already emits traces, but the spans do not use
OpenInference attributes directly.

It helps you answer one question: where should translation happen before Phoenix
renders the trace?

Phoenix uses [OpenInference semantic conventions](/docs/phoenix/tracing/concepts-tracing/otel-openinference/semantic-conventions) to render AI traces: span kinds, chat messages, token counts, tool calls, retrieval documents, sessions, users, and metadata.

## Choose where translation happens

| If your traces use | Where translation happens | What you do |
| :--- | :--- | :--- |
| **OpenInference** | Nowhere | Send spans to Phoenix. |
| **OpenTelemetry GenAI** | Phoenix ingest | Send spans to Phoenix over OTLP. |
| **OpenLIT or OpenLLMetry** | Your app, before export | Add the matching OpenInference span processor. |
| **Exported or historical traces** | Import step | Use [Import existing traces](/docs/phoenix/tracing/how-to-tracing/importing-and-exporting-traces/importing-existing-traces). |
| **Custom convention** | Your instrumentation pipeline | Map your attributes to OpenInference, or write a custom span processor. |

Translation maps source attributes, such as `gen_ai.*` or OpenLIT/OpenLLMetry fields, to OpenInference attributes such as `openinference.span.kind`, `llm.input_messages`, and `llm.token_count.*`. Phoenix uses those OpenInference fields to render the trace UI.

## Convert OpenTelemetry GenAI at ingest

Use this path when your SDK or framework already emits `gen_ai.*` spans. Phoenix `15.10.0` and later converts supported OpenTelemetry GenAI attributes at ingest. Existing OpenInference attributes take precedence when both are present.

Phoenix converts span kind, provider and system, model, messages, token counts, session ID, tool definitions and tool call spans, retrieval documents, response ID, response model, and finish reason.

The example below emits one OTel GenAI span and sends it to Phoenix.

```python
import json

from opentelemetry import trace
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.trace import Status, StatusCode
from phoenix.otel import SimpleSpanProcessor

tracer_provider = TracerProvider(
    resource=Resource.create({"openinference.project.name": "otel-genai-app"})
)
tracer_provider.add_span_processor(SimpleSpanProcessor(protocol="http/protobuf"))
trace.set_tracer_provider(tracer_provider)

tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("chat gpt-4o-mini") as span:
    span.set_attributes(
        {
            "gen_ai.operation.name": "chat",
            "gen_ai.provider.name": "openai",
            "gen_ai.request.model": "gpt-4o-mini",
            "gen_ai.input.messages": json.dumps(
                [
                    {
                        "role": "user",
                        "parts": [{"type": "text", "content": "What is Phoenix?"}],
                    }
                ]
            ),
            "gen_ai.output.messages": json.dumps(
                [
                    {
                        "role": "assistant",
                        "parts": [
                            {
                                "type": "text",
                                "content": "Phoenix is an open-source AI observability tool.",
                            }
                        ],
                        "finish_reason": "stop",
                    }
                ]
            ),
            "gen_ai.usage.input_tokens": 12,
            "gen_ai.usage.output_tokens": 9,
        }
    )
    span.set_status(Status(StatusCode.OK))

tracer_provider.force_flush()
tracer_provider.shutdown()
```

## Translate OpenLIT or OpenLLMetry before export

Use this path when your traces come from OpenLIT, OpenLLMetry, or Traceloop. Add the matching OpenInference processor before spans reach the exporter, so Phoenix receives OpenInference-shaped attributes.

<Warning>
Processor order matters. Add the translation processor before the exporter processor. See [Span processor](/docs/phoenix/tracing/concepts-tracing/otel-openinference/span-processor) for how processors run.
</Warning>

Use the processor that matches the source of your spans:

```python
from opentelemetry import trace
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from phoenix.otel import BatchSpanProcessor

# Choose the package that matches your source traces.
from openinference.instrumentation.openlit import OpenInferenceSpanProcessor
# from openinference.instrumentation.openllmetry import OpenInferenceSpanProcessor

tracer_provider = TracerProvider(
    resource=Resource.create({"openinference.project.name": "translated-traces"})
)
trace.set_tracer_provider(tracer_provider)

# 1. Translate spans to OpenInference.
tracer_provider.add_span_processor(OpenInferenceSpanProcessor())

# 2. Export the translated spans to Phoenix.
tracer_provider.add_span_processor(BatchSpanProcessor(protocol="http/protobuf"))
```

## Verify translated spans

After traces arrive, open the trace in Phoenix and check:

* Span kind renders as `LLM`, `TOOL`, `RETRIEVER`, `EMBEDDING`, `AGENT`, or another expected OpenInference kind.
* LLM spans show chat messages from `llm.input_messages` and `llm.output_messages`.
* Token counts appear on the span and roll up to the trace.
* The original source attributes, such as `gen_ai.*`, are still available for filtering and debugging.

## Learn more

* **Target format:** Phoenix renders AI traces from [OpenInference semantic conventions](/docs/phoenix/tracing/concepts-tracing/otel-openinference/semantic-conventions), including span kind, messages, token counts, tool calls, retrieval documents, sessions, users, and metadata.
* **Processor order:** OpenLIT and OpenLLMetry translation must run before export. See [Span processor](/docs/phoenix/tracing/concepts-tracing/otel-openinference/span-processor).
* **Tracing pipeline:** See [OpenTelemetry and OpenInference](/docs/phoenix/tracing/concepts-tracing/otel-openinference/overview) for how tracers, processors, exporters, and OpenInference fit together.
* **Historical traces:** Use [Import existing traces](/docs/phoenix/tracing/how-to-tracing/importing-and-exporting-traces/importing-existing-traces) when traces already exist outside the live OTLP pipeline.
