Tracing records what happens inside an LLM application. A trace can show model calls, retrieval, tool calls, agent steps, inputs, outputs, timing, token counts, errors, and metadata.

Use this page to understand the data Phoenix receives before you instrument your app.

## Traces and spans

A trace records the path a request takes through your application. The first span in a trace is the root span, and it represents the request from start to finish.

A span represents one operation inside the trace. A span records what happened during that operation, when it started, when it ended, and which attributes describe it.

Spans can be nested. A child span represents work that happened inside a parent span, such as a retriever span or tool span inside an agent trace.

## How tracing works

<Frame caption="Phoenix receives traces over OTLP">
  <img src="https://storage.googleapis.com/arize-assets/phoenix/assets/images/deployment.png" alt="Applications export traces over OTLP to the Phoenix server." />
</Frame>

First, instrumentation creates spans from your application. You can use auto-instrumentation for supported frameworks, or you can create spans manually around custom code.

Second, an exporter sends spans out of your application. With Phoenix OTEL, the exporter is configured when you call `register()`.

Third, Phoenix receives spans as a collector and shows them in the UI. When you start Phoenix locally or connect to a remote Phoenix instance, Phoenix can receive spans from applications that export traces to it.

Phoenix receives traces over OpenTelemetry Protocol, or OTLP. Phoenix supports OTLP over HTTP, and Phoenix OTEL can configure the exporter for you.

## Projects

A project is a collection of traces. Use projects to separate applications, environments, evaluation runs, or versions. To configure projects, see [Set up projects](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-projects).

## OpenTelemetry and OpenInference

Phoenix tracing is built on OpenTelemetry and OpenInference.

OpenTelemetry defines how spans are created, processed, and exported. OpenInference adds GenAI-specific attributes on top of OpenTelemetry, such as span kinds, messages, model names, token counts, retrieved documents, and tool calls.

Phoenix uses [OpenInference semantic conventions](https://github.com/Arize-ai/openinference/blob/main/spec/semantic_conventions.md) as its standard trace format. When possible, use OpenInference attributes so Phoenix and other OpenInference-aware tools can read the same trace data.

## Span kinds

When a span is created, it should include an `openinference.span.kind` attribute. Phoenix uses the span kind to render the trace tree and choose which attributes to show.

<Frame caption="The span kinds supported by OpenInference tracing">
  <img src="https://storage.googleapis.com/arize-assets/phoenix/assets/images/span_kinds.png" alt="OpenInference span kinds used by Phoenix, including chain, retriever, reranker, LLM, embedding, tool, agent, guardrail, evaluator, prompt, and unknown." />
</Frame>

Common span kinds include `CHAIN`, `RETRIEVER`, `RERANKER`, `LLM`, `EMBEDDING`, `TOOL`, `AGENT`, `GUARDRAIL`, `EVALUATOR`, `PROMPT`, and `UNKNOWN`. For the full list and per-kind attributes, see [Span kinds](/docs/phoenix/tracing/concepts-tracing/otel-openinference/span-kinds).

## Span attributes

Attributes are key-value pairs that describe a span. For example, an LLM span can capture the model name, invocation parameters, token count, input messages, and output messages.

Attributes have the following rules:

* Keys must be non-null string values.
* Values must be a non-null string, boolean, floating point value, integer, or an array of those values.

Semantic attributes are standard attribute names for common operations. Use semantic attributes where possible so Phoenix can read your trace data consistently. For details, see [Semantic conventions](/docs/phoenix/tracing/concepts-tracing/otel-openinference/semantic-conventions).

## Common tracing questions

### How do I log traces?

To log traces, instrument your application manually or with an OpenInference instrumentation package. To send traces to a remote Phoenix instance, set `PHOENIX_COLLECTOR_ENDPOINT` to the Phoenix URL before your app starts.

<Tabs>
<Tab title="Local Phoenix">
When Phoenix runs locally on the default port of `6006`, no extra configuration is needed.

```python
import phoenix as px
from openinference.instrumentation.langchain import LangChainInstrumentor
from phoenix.otel import register

px.launch_app()

tracer_provider = register()
LangChainInstrumentor().instrument(tracer_provider=tracer_provider)

# Run your LangChain application.
```
</Tab>

<Tab title="Remote Phoenix">
If you are running a remote instance of Phoenix, set `PHOENIX_COLLECTOR_ENDPOINT` to its URL before registering. Include the scheme because the value is parsed as a URL.

```python
import os
from openinference.instrumentation.langchain import LangChainInstrumentor
from phoenix.otel import register

# Assume Phoenix is running at 162.159.135.42:6007.
os.environ["PHOENIX_COLLECTOR_ENDPOINT"] = "http://162.159.135.42:6007"

tracer_provider = register()
LangChainInstrumentor().instrument(tracer_provider=tracer_provider)

# Run your LangChain application.
```

See [Environments](/docs/phoenix/environments) for the rest of the connection settings.
</Tab>
</Tabs>

### How do I turn off tracing?

Tracing can be paused temporarily or disabled permanently.

Use `suppress_tracing` when a block of code should not emit traces. For example, you may want to skip tracing for document chunking or evaluation code.

```python
from phoenix.trace import suppress_tracing

with suppress_tracing():
    # Code running inside this block does not generate traces.
    ...

# Tracing resumes outside the block.
```

To disable an auto-instrumentor permanently, call `.uninstrument()` on the instrumentor.

```python
LangChainInstrumentor().uninstrument()
LlamaIndexInstrumentor().uninstrument()
OpenAIInstrumentor().uninstrument()
```

### How do I get token counts when streaming with OpenAI?

To get token counts when streaming, install `openai>=1.26` and set `stream_options={"include_usage": True}` when calling `create`. For more information, see the [OpenAI streaming usage announcement](https://community.openai.com/t/usage-stats-now-available-when-using-streaming-with-the-chat-completions-api-or-completions-api/738156).

```python
response = openai.OpenAI().chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[{"role": "user", "content": "Write a haiku."}],
    max_tokens=20,
    stream=True,
    stream_options={"include_usage": True},
)
```

### Why are traces missing for a custom LangChain component?

If you customize a LangChain component, such as a retriever, traces may not appear unless the component inherits from the LangChain base classes. The example below shows a custom retriever that inherits from the LangChain retriever base class.

```python expandable
from typing import List

from langchain_core.callbacks import CallbackManagerForRetrieverRun
from langchain_core.retrievers import BaseRetriever, Document
from openinference.instrumentation.langchain import LangChainInstrumentor
from opentelemetry import trace as trace_api
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk import trace as trace_sdk
from opentelemetry.sdk.trace.export import SimpleSpanProcessor

endpoint = "http://127.0.0.1:6006/v1/traces"
tracer_provider = trace_sdk.TracerProvider()
trace_api.set_tracer_provider(tracer_provider)
tracer_provider.add_span_processor(SimpleSpanProcessor(OTLPSpanExporter(endpoint)))

LangChainInstrumentor().instrument()


class CustomRetriever(BaseRetriever):
    """A custom retriever that returns the top k matching documents."""

    k: int
    """Number of top results to return."""

    def _get_relevant_documents(
        self, query: str, *, run_manager: CallbackManagerForRetrieverRun
    ) -> List[Document]:
        """Return matching documents."""
        matching_documents: List[Document] = []

        for index in range(self.k):
            matching_documents.append(Document(page_content=f"dummy content at {index}", score=1.0))
        return matching_documents


retriever = CustomRetriever(k=3)


if __name__ == "__main__":
    documents = retriever.invoke("what is the meaning of life?")
```
