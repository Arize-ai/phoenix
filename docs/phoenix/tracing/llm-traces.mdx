Phoenix collects traces from AI applications over OpenTelemetry. It also has integrations with LlamaIndex, LangChain, OpenAI, and others.

<AgentAssistedOnboardingPrereq />

LLM tracing records the paths taken by requests as they propagate through multiple steps or components of an LLM application. For example, when a user interacts with an LLM application, tracing can capture the sequence of operations, such as document retrieval, embedding generation, language model invocation, and response generation to provide a detailed timeline of the request's execution.

Tracing helps you understand how your LLM application works. Phoenix accepts traces over the OpenTelemetry protocol (OTLP), and it works with many frameworks, SDKs, and languages, including [LlamaIndex](/docs/phoenix/integrations/python/llamaindex), [LangChain](/docs/phoenix/integrations/python/langchain), [DSPy](/docs/phoenix/integrations/python/dspy/dspy-tracing), [OpenAI](/docs/phoenix/integrations/llm-providers/openai), [Bedrock](/docs/phoenix/integrations/llm-providers/amazon-bedrock), [Mistral](/docs/phoenix/integrations/llm-providers/mistralai), [Vertex](/docs/phoenix/integrations/llm-providers/vertexai), [Python](/docs/phoenix/integrations/python/agno), and [TypeScript](/docs/phoenix/integrations/typescript/beeai).

Trace data helps you find performance and reliability issues in your application. After Phoenix receives traces, use [Observe](/docs/phoenix/observe/explore-traces) to inspect projects, sessions, filters, metrics, and dashboards.

## What you can inspect

Phoenix stores span details that help you debug LLM application behavior:

* **Latency**: Find slow LLM, retriever, tool, and custom spans.
* **Token usage and cost**: See which LLM calls use the most tokens and estimated cost.
* **Errors**: Review exceptions, rate limits, and failed tool calls.
* **Retrieved documents**: Check document text, scores, and order returned by retrievers.
* **Embeddings**: Review embedding input text and model attributes used during retrieval.
* **LLM parameters**: Check model name, temperature, system prompts, and other invocation settings.
* **Prompt templates**: See template text, versions, and variables when you send them.
* **Tools and function calls**: Inspect available tool schemas, selected tools, tool messages, and function-call inputs.
