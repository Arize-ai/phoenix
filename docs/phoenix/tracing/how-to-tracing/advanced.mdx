Use these patterns when your basic tracing setup works, but you need more control over what Phoenix receives or how traces connect across your system.

Phoenix tracing uses OpenTelemetry to create, process, and export spans. It uses OpenInference to describe AI work, such as LLM calls, tool calls, retrieval, and agent steps. The pages below explain the practical pieces you are most likely to need when a standard setup is not enough.

| If you need to... | Use... |
| :--- | :--- |
| Understand how Phoenix reads AI trace data | [OpenTelemetry and OpenInference](/docs/phoenix/tracing/concepts-tracing/otel-openinference/overview) |
| Keep one trace connected across services or background work | [Context propagation](/docs/phoenix/tracing/concepts-tracing/otel-openinference/context-propagation) |

## How the pieces fit

OpenTelemetry defines the tracing pipeline. Your application creates spans, a span processor prepares them for export, and an exporter sends them to Phoenix or to an OpenTelemetry Collector.

OpenInference defines the AI fields inside those spans. Phoenix uses OpenInference span kinds and attributes to show LLM calls, tools, retrievers, agents, inputs, outputs, token counts, sessions, and users in the UI.

You usually do not need to configure every OpenTelemetry component yourself. Start with [Auto-instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-using-phoenix-otel) or [Manual instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/instrument), then use the patterns on this page when you need more control.

## Suppress tracing

Tracing can be paused for one block of code or disabled for an instrumentor.

### Pause tracing for a block of code

Use `suppress_tracing` when a section of code should not generate traces. For example, you may want to skip document chunking or internal evaluation calls.

```python
from phoenix.otel import suppress_tracing

with suppress_tracing():
    # Code running inside this block does not generate traces.
    ...
# Tracing resumes outside the block.
...
```

### Disable an auto-instrumentor

Call `.uninstrument()` on an auto-instrumentor to remove tracing for that library.

```python
LangChainInstrumentor().uninstrument()
LlamaIndexInstrumentor().uninstrument()
OpenAIInstrumentor().uninstrument()
```

## Filter spans before export

Use a custom `SpanProcessor` when you need to filter or modify spans before Phoenix receives them. For example, you can skip spans that include redundant data or sensitive values.

<Tabs>
  <Tab title="Python" icon="python">

    ```python
    from phoenix.otel import BatchSpanProcessor, register
    from opentelemetry.context import Context
    from opentelemetry.sdk.trace import ReadableSpan, Span


    class FilteringSpanProcessor(BatchSpanProcessor):
        def _filter_condition(self, span: Span) -> bool:
            # Return True if the span should be filtered out.
            return span.name == "secret_span"

        def on_start(self, span: Span, parent_context: Context) -> None:
            if self._filter_condition(span):
                return
            super().on_start(span, parent_context)

        def on_end(self, span: ReadableSpan) -> None:
            if self._filter_condition(span):
                return
            super().on_end(span)


    tracer_provider = register()
    tracer_provider.add_span_processor(
        FilteringSpanProcessor(
            endpoint="http://localhost:6006/v1/traces",
            protocol="http/protobuf",
        )
    )
    ```

    The example filters out spans named `secret_span` by skipping the `on_start` and `on_end` hooks on the inherited `BatchSpanProcessor`. You can extend the same pattern to redact sensitive values when you want to keep the span.
