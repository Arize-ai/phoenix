Use these patterns after basic tracing is working. They help you control which spans Phoenix receives, which attributes are stored, and how spans stay connected across services.

Phoenix tracing uses OpenTelemetry to create and export spans. It uses OpenInference attributes to describe AI work, such as LLM calls, tool calls, retrieval, and agent steps.

## What you can control

- **Trace shape:** connect spans across services, threads, and async work.
- **Trace volume:** sample traces or filter spans before export.
- **Trace contents:** hide inputs, outputs, images, prompts, tools, or other attributes.
- **Trace media:** capture image content in LLM messages.

## How the pieces fit

OpenTelemetry defines the tracing pipeline. Your application creates spans, a span processor prepares them for export, and an exporter sends them to Phoenix or to an OpenTelemetry Collector.

OpenInference defines the AI fields inside those spans. Phoenix uses OpenInference span kinds and attributes to show LLM calls, tools, retrievers, agents, inputs, outputs, token counts, sessions, and users in the UI.

You usually do not need to configure every OpenTelemetry component yourself. Start with [Auto-instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-using-phoenix-otel) or [Manual instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/instrument), then use the patterns on this page when you need more control.

## Suppress tracing

Use suppression when a specific block of code should not create spans. Use it for health checks, internal logging, setup work, or model calls that should stay out of traces.

### Pause tracing for a block of code

```python
from phoenix.otel import suppress_tracing

with suppress_tracing():
    # Code running inside this block does not generate traces.
    ...
# Tracing resumes outside the block.
...
```

### Disable an auto-instrumentor

Call `.uninstrument()` to stop tracing for a whole instrumented library.

```python
from openinference.instrumentation.openai import OpenAIInstrumentor

OpenAIInstrumentor().instrument()
OpenAIInstrumentor().uninstrument()
```

## Filter spans before export

Use a span processor when you need a rule that runs on every span before export. For example, you can drop noisy spans or rewrite attributes that are specific to your app.

<Tabs>
  <Tab title="Python" icon="python">

    ```python
    from phoenix.otel import BatchSpanProcessor, register
    from opentelemetry.sdk.trace import ReadableSpan


    class FilteringSpanProcessor(BatchSpanProcessor):
        def _should_drop(self, span: ReadableSpan) -> bool:
            # Return True if the span should be filtered out.
            return span.name == "secret_span"

        def on_end(self, span: ReadableSpan) -> None:
            if self._should_drop(span):
                return
            super().on_end(span)


    tracer_provider = register()
    # Phoenix replaces the default processor when you add a custom one.
    tracer_provider.add_span_processor(
        FilteringSpanProcessor(
            endpoint="http://localhost:6006/v1/traces",
            protocol="http/protobuf",
        )
    )
    ```

    The example drops spans named `secret_span` before export. If you need to hide common OpenInference fields such as inputs, outputs, images, prompts, or tools, use [Mask and redact data](/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes) first.

  </Tab>
</Tabs>
