Track LLM spend in Phoenix. Phoenix calculates estimated cost from OpenInference token counts and model prices, then rolls cost up across spans, traces, sessions, projects, and experiments.

## How cost tracking works

1. Your app sends an LLM span with `openinference.span.kind`, `llm.model_name`, and token counts.
2. Phoenix matches `llm.model_name`, optional `llm.provider`, and the span start time to a built-in or custom model.
3. Phoenix applies prompt, completion, and token-type prices to the span.
4. Phoenix stores span costs and aggregates them across the app.

## Set up cost tracking

<Steps>
  <Step title="Use built-in prices">
    Phoenix includes built-in prices for many common models. For many OpenInference auto-instrumented providers, the span already includes the model name and token counts Phoenix needs.
  </Step>

  <Step title="Send token counts">
    If you create LLM spans manually or use OpenTelemetry directly, send the OpenInference token attributes yourself.

    | Attribute | Use |
    | :-- | :-- |
    | `openinference.span.kind` | Set to `LLM` so Phoenix treats the span as a model call |
    | `llm.model_name` | Model name used for price lookup |
    | `llm.provider` | Optional provider used to narrow a price match |
    | `llm.token_count.prompt` | Prompt token count |
    | `llm.token_count.completion` | Completion token count |
    | `llm.token_count.total` | Optional total token count |
  </Step>

  <Step title="Add or override pricing">
    Go to **Settings > Models** and click **Add Model**. Set a regex **Name pattern** that matches `llm.model_name`, optionally set a provider, then enter prompt and completion prices in USD per 1M tokens.

    Custom models take precedence over built-in models when their pattern matches. Use **Start date** for prices that should match spans on or after the span start date.
  </Step>

  <Step title="Inspect costs">
    Use cost fields in span, trace, session, project, and experiment views. You can also filter spans, traces, and sessions by `total_cost`, `prompt_cost`, and `completion_cost`.
  </Step>
</Steps>

Use the Phoenix model form to add custom pricing or override a built-in match.

## Token types

Phoenix supports basic prompt and completion pricing, plus detailed token types for providers that report them.

| Token type | Category | Attribute |
| :-- | :-- | :-- |
| `input` | Prompt | `llm.token_count.prompt` |
| `output` | Completion | `llm.token_count.completion` |
| `cache_read` | Prompt | `llm.token_count.prompt_details.cache_read` |
| `cache_write` | Prompt | `llm.token_count.prompt_details.cache_write` |
| `audio` | Prompt or completion | `llm.token_count.prompt_details.audio`, `llm.token_count.completion_details.audio` |
| `image` | Prompt or completion | `llm.token_count.prompt_details.image`, `llm.token_count.completion_details.image` |
| `reasoning` | Completion | `llm.token_count.completion_details.reasoning` |

Custom model pricing must include `input` and `output` token types. You can add cache, audio, reasoning, image, or custom token types in **Settings > Models**. If a detailed token type does not have its own price, Phoenix falls back to the model's `input` price for prompt tokens and `output` price for completion tokens.

## View cost data

Once Phoenix has token counts and model prices, cost appears across the app:

* **Spans** — cost for an individual LLM call, including prompt, completion, and token-type details.
* **Traces** — total cost for one request across all LLM spans in the trace.
* **Sessions** — cost across multi-turn conversations.
* **Projects** — cost over time and top models by cost.
* **Experiments** — total and per-run cost for traced experiment runs.

Example span filters:

```text
total_cost > 0.01
```

```text
any(cost_detail.token_type == "cache_read" for cost_detail in cost_details)
```
