Start where tracing is automatic. Install the OpenInference instrumentor for your model client or AI framework, attach it once, and calls are traced.

## Auto-instrument with a coding agent

`px setup` connects your app to Phoenix, hands instrumentation to your coding agent, and verifies that traces arrive.

<Steps>
  <Step title={<span className="step-title">Start Phoenix</span>}>
    If you already have a Phoenix deployment, skip this step.

    ```bash
    uvx arize-phoenix serve
    ```
  </Step>

  <Step title={<span className="step-title">Run setup from your app</span>}>
    In a new terminal, run one of these from your app's root directory:

    <CodeGroup>
    ```bash npx
    npx -y @arizeai/phoenix-cli setup
    ```

    ```bash Install
    npm i -g @arizeai/phoenix-cli && px setup
    ```
    </CodeGroup>
  </Step>
</Steps>

During setup, choose Claude Code, Codex, Cursor, or OpenCode. When prompted to install agent skills, answer yes. You can also run `px setup skills` later. For CI, unsupported agents, and setup flags, see [Agent-Assisted Setup](/docs/phoenix/agent-assisted-setup).

You can also start from the Phoenix UI. In a project with no traces, open **Spans** or **Traces**, choose **Trace your app**, then pick the integration that matches your stack.

## Auto-instrument with code

Use this path when you want to add tracing yourself. Choose the OpenInference package for your stack from [Supported integrations](/docs/phoenix/integrations), install it with Phoenix OTEL, then register tracing in your app.

<Steps>
  <Step title={<span className="step-title">Install</span>}>
    <Tabs>
      <Tab title="Python" icon="python">
        ```bash
        pip install arize-phoenix-otel
        pip install openinference-instrumentation-openai
        ```
      </Tab>
      <Tab title="JS/TS" icon="js">
        ```bash
        npm install @arizeai/phoenix-otel
        npm install @arizeai/openinference-instrumentation-openai
        ```
      </Tab>
    </Tabs>

    The commands above use OpenAI as an example. For another framework or provider, install its package from [Supported integrations](/docs/phoenix/integrations).

    <Accordion title="Go setup">
    Phoenix does not ship a branded `phoenix-otel` SDK wrapper for Go. Configure the standard [OpenTelemetry Go SDK](https://opentelemetry.io/docs/languages/go/) directly and point an OTLP/HTTP exporter at Phoenix. End-to-end examples live in the Go integration pages: [OpenAI Go SDK](/docs/phoenix/integrations/llm-providers/openai/openai-go-sdk), [Anthropic SDK Go](/docs/phoenix/integrations/llm-providers/anthropic/anthropic-sdk-go), and [Gemini Go SDK](/docs/phoenix/integrations/llm-providers/google-gen-ai/gemini-go-sdk).
    </Accordion>
  </Step>

  <Step title={<span className="step-title">Register and instrument</span>}>
    Set environment variables to connect to your Phoenix instance:

    ```bash
    export PHOENIX_API_KEY="your-api-key"

    # Local (default, no API key required)
    export PHOENIX_COLLECTOR_ENDPOINT="http://localhost:6006"

    # A remote Phoenix deployment
    # export PHOENIX_COLLECTOR_ENDPOINT="https://your-phoenix.example.com"

    # Self-hosted
    # export PHOENIX_COLLECTOR_ENDPOINT="https://your-phoenix-instance.com"
    ```

    Call `register()` to initialize tracing. The SDK automatically reads your environment variables.

    <Tabs>
      <Tab title="Python" icon="python">
        ```python
        from phoenix.otel import register

        tracer_provider = register(
            project_name="my-llm-app",
            auto_instrument=True,  # automatically instruments OpenAI, LangChain, etc.
        )
        ```

        <Accordion title="Configuration options">
          | Parameter | Description |
          |-----------|-------------|
          | `project_name` | Project name in Phoenix, from this argument or the `PHOENIX_PROJECT` environment variable. `PHOENIX_PROJECT_NAME` is also supported as an alias. |
          | `auto_instrument` | Automatically instrument all supported libraries |
          | `batch` | Process spans in batch (default: `False`) |
          | `endpoint` | Custom collector endpoint URL |
          | `protocol` | Transport protocol: `"grpc"` or `"http/protobuf"` |
          | `headers` | Headers to send with each span payload |
        </Accordion>
      </Tab>

      <Tab title="JS/TS" icon="js">
        ```typescript
        import OpenAI from "openai";
        import { register, registerInstrumentations } from "@arizeai/phoenix-otel";
        import { OpenAIInstrumentation } from "@arizeai/openinference-instrumentation-openai";

        register({ projectName: "my-llm-app" });

        const instrumentation = new OpenAIInstrumentation();
        instrumentation.manuallyInstrument(OpenAI);

        registerInstrumentations({
          instrumentations: [instrumentation],
        });
        ```

        <Info>
        ESM projects require calling `manuallyInstrument()` on the client class. CommonJS projects can skip this step.
        </Info>

        <Accordion title="Configuration options">
          | Parameter | Type | Default | Description |
          |-----------|------|---------|-------------|
          | `projectName` | `string` | `"default"` | Project name in Phoenix |
          | `url` | `string` | `"http://localhost:6006"` | Phoenix server URL |
          | `apiKey` | `string` | None | API key for authentication |
          | `batch` | `boolean` | `true` | Use batch span processing |
          | `headers` | `Record<string, string>` | `{}` | Custom headers for OTLP requests |
          | `instrumentations` | `Instrumentation[]` | None | Instrumentations to register |
          | `global` | `boolean` | `true` | Register as the global tracer provider |
          | `spanProcessors` | `SpanProcessor[]` | None | Custom span processors (overrides default exporter) |
          | `diagLogLevel` | `DiagLogLevel` | None | Enable diagnostic logging |
        </Accordion>
      </Tab>
    </Tabs>

    <Tip>
    You can find your collector endpoint and API key in the **Settings** page of your Phoenix instance.
    </Tip>
  </Step>

  <Step title={<span className="step-title">Run your app</span>}>
    Run your application as usual. Phoenix receives spans from the supported model clients, frameworks, or tools you installed.
  </Step>
</Steps>

---

<Note>
Spans may not be exported if still queued in the processor when your process exits. With `batch: true`, call `shutdown()` to explicitly flush before exit. Alternatively, use `batch: false` for immediate export.
</Note>

## Learn more

- **What auto captures:** auto-instrumentors set [OpenInference semantic conventions](/docs/phoenix/tracing/concepts-tracing/otel-openinference/semantic-conventions) automatically, including model names, messages, token counts, inputs, and outputs.

- **Group traces into conversations:** add `session.id` and `user.id` to follow multi-turn interactions. See [Set up projects and sessions](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-projects-and-sessions#sessions).

- **Enrich traces with custom data:** attach metadata, tags, and custom attributes to auto-instrumented spans. See [Customize your traces](/docs/phoenix/tracing/how-to-tracing/add-metadata/customize-spans).

- **Control what is captured:** hide sensitive inputs, suppress tracing for specific calls, or redact span attributes. See [Mask and redact data](/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes).

- **Add spans that auto-instrumentation missed:** add manual spans around custom logic. See [Manual instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/instrument).

- **Tune the SDK setup:** configure batching, custom endpoints, headers, sampling, and full SDK options. See [Python arize-phoenix-otel](/docs/phoenix/sdk-api-reference/python/arize-phoenix-otel) or [TypeScript @arizeai/phoenix-otel](/docs/phoenix/sdk-api-reference/typescript/arizeai-phoenix-otel).
