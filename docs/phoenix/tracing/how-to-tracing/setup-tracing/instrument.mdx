Use manual instrumentation when you need spans around code that auto-instrumentation does not capture. Common cases include custom tools, routing logic, agent loops, retrieval steps, and unsupported SDKs.

If a supported model client or framework already has an OpenInference integration, start with [Auto-instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-using-phoenix-otel). Then add manual spans around your own code.

## Add spans with a coding agent

`px setup` can connect your app to Phoenix and hand the tracing work to a supported coding agent. After setup, ask the agent to wrap custom tools or application steps with manual spans.

<Steps>
  <Step title="Start Phoenix">
    If you already have a Phoenix deployment, skip this step.

    ```bash
    uvx arize-phoenix serve
    ```
  </Step>

  <Step title="Run setup from your app">
    In a new terminal, run one of these from your app's root directory:

    <CodeGroup>
    ```bash npx
    npx -y @arizeai/phoenix-cli setup
    ```

    ```bash Install
    npm i -g @arizeai/phoenix-cli && px setup
    ```
    </CodeGroup>
  </Step>

  <Step title="Ask for manual spans">
    Ask your coding agent to wrap custom logic with Phoenix manual spans:

    ```text
    Add manual spans around my custom tool functions and agent steps using Phoenix and OpenInference conventions. Verify that traces arrive in Phoenix.
    ```
  </Step>
</Steps>

During setup, choose Claude Code, Codex, Cursor, or OpenCode. When prompted to install agent skills, answer yes. You can also run `px setup skills` later. For CI, unsupported agents, and setup flags, see [Agent-Assisted Setup](/docs/phoenix/agent-assisted-setup).

## Add spans with code

Use this path when you want to write the spans yourself. First, register tracing. Then wrap the code you want to see in Phoenix.

<Steps>
  <Step title="Install">
    <Tabs>
      <Tab title="Python" icon="python">
        ```bash
        pip install "arize-phoenix-otel>=0.16.0"
        ```
      </Tab>

      <Tab title="JS/TS" icon="js">
        ```bash
        npm install @arizeai/phoenix-otel
        ```
      </Tab>

      <Tab title="Go" icon="golang">
        Phoenix does not ship a branded Go wrapper. Use the OpenTelemetry Go SDK with the OpenInference Go packages.

        ```bash
        go get github.com/Arize-ai/openinference/go/openinference-semantic-conventions
        go get github.com/Arize-ai/openinference/go/openinference-instrumentation
        go get go.opentelemetry.io/otel
        go get go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp
        go get go.opentelemetry.io/otel/sdk
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Register tracing">
    Set the Phoenix endpoint for your environment:

    ```bash
    # Local Phoenix, no API key required
    export PHOENIX_COLLECTOR_ENDPOINT="http://localhost:6006"

    # A remote Phoenix deployment
    # export PHOENIX_COLLECTOR_ENDPOINT="https://your-phoenix.example.com"
    # export PHOENIX_API_KEY="your-api-key"
    ```

    <Tabs>
      <Tab title="Python" icon="python">
        ```python
        from phoenix.otel import register

        tracer_provider = register(project_name="my-llm-app")
        tracer = tracer_provider.get_tracer(__name__)
        ```
      </Tab>

      <Tab title="JS/TS" icon="js">
        ```typescript
        import { register } from "@arizeai/phoenix-otel";

        const provider = register({
          projectName: "my-llm-app",
        });
        ```
      </Tab>

      <Tab title="Go" icon="golang">
        Configure an OTLP/HTTP exporter pointed at Phoenix, then get a tracer.

        ```go
        package main

        import (
            "context"
            "os"
            "strings"

            "go.opentelemetry.io/otel"
            "go.opentelemetry.io/otel/attribute"
            "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp"
            "go.opentelemetry.io/otel/sdk/resource"
            sdktrace "go.opentelemetry.io/otel/sdk/trace"
            semconvotel "go.opentelemetry.io/otel/semconv/v1.26.0"
        )

        func phoenixTraceEndpoint(endpoint string) string {
            endpoint = strings.TrimRight(endpoint, "/")
            if strings.HasSuffix(endpoint, "/v1/traces") {
                return endpoint
            }
            return endpoint + "/v1/traces"
        }

        func initTracer(ctx context.Context) (*sdktrace.TracerProvider, error) {
            opts := []otlptracehttp.Option{
                otlptracehttp.WithEndpoint("localhost:6006"),
                otlptracehttp.WithURLPath("/v1/traces"),
                otlptracehttp.WithInsecure(),
            }
            if endpoint := os.Getenv("PHOENIX_COLLECTOR_ENDPOINT"); endpoint != "" {
                headers := map[string]string{}
                if apiKey := os.Getenv("PHOENIX_API_KEY"); apiKey != "" {
                    headers["Authorization"] = "Bearer " + apiKey
                }
                opts = []otlptracehttp.Option{
                    otlptracehttp.WithEndpointURL(phoenixTraceEndpoint(endpoint)),
                    otlptracehttp.WithHeaders(headers),
                }
            }

            exporter, err := otlptracehttp.New(ctx, opts...)
            if err != nil {
                return nil, err
            }
            res, _ := resource.New(ctx, resource.WithAttributes(
                semconvotel.ServiceName("my-llm-app"),
                attribute.String("openinference.project.name", "my-llm-app"),
            ))
            tp := sdktrace.NewTracerProvider(
                sdktrace.WithBatcher(exporter),
                sdktrace.WithResource(res),
            )
            otel.SetTracerProvider(tp)
            return tp, nil
        }
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Wrap your code">
    Use span kinds that match the work the code performs. `CHAIN` is a general application step, `TOOL` is a function or API call used by an agent, and `AGENT` is an agent run that may contain model and tool calls.

    <Tabs>
      <Tab title="Python" icon="python">
        Decorators are the shortest path for functions:

        ```python
        @tracer.chain
        def normalize_question(question: str) -> str:
            return question.strip()


        @tracer.tool
        def lookup_order(order_id: str) -> dict[str, str]:
            return {"status": "shipped"}
        ```

        Use a span block when you need to set fields yourself:

        ```python
        from opentelemetry.trace import Status, StatusCode

        with tracer.start_as_current_span(
            "rank-documents",
            openinference_span_kind="reranker",
        ) as span:
            span.set_input({"query": query, "documents": documents})
            ranked = rank(query, documents)
            span.set_output(ranked)
            span.set_status(Status(StatusCode.OK))
        ```
      </Tab>

      <Tab title="JS/TS" icon="js">
        Function wrappers are the shortest path for functions:

        ```typescript
        import { traceChain, traceTool, withSpan } from "@arizeai/phoenix-otel";

        const normalizeQuestion = traceChain(
          (question: string): string => question.trim(),
          { name: "normalize-question" }
        );

        const lookupOrder = traceTool(
          async (orderId: string): Promise<{ status: string }> => {
            return { status: "shipped" };
          },
          { name: "lookup-order" }
        );

        const rankDocuments = withSpan(
          async (query: string, documents: string[]) => {
            return rank(query, documents);
          },
          { name: "rank-documents", kind: "RERANKER" }
        );
        ```
      </Tab>

      <Tab title="Go" icon="golang">
        Go does not have decorators. Start a span, set OpenInference attributes, and end the span.

        ```go
        import (
            "context"

            semconv "github.com/Arize-ai/openinference/go/openinference-semantic-conventions"
            "go.opentelemetry.io/otel"
            "go.opentelemetry.io/otel/attribute"
            "go.opentelemetry.io/otel/codes"
            "go.opentelemetry.io/otel/trace"
        )

        func lookupOrder(ctx context.Context, orderID string) (string, error) {
            tracer := otel.Tracer("my-llm-app")
            ctx, span := tracer.Start(ctx, "lookup-order",
                trace.WithAttributes(
                    attribute.String(semconv.OpenInferenceSpanKind, semconv.SpanKindTool),
                    attribute.String(semconv.InputValue, orderID),
                ),
            )
            defer span.End()

            status := "shipped"
            span.SetAttributes(attribute.String(semconv.OutputValue, status))
            span.SetStatus(codes.Ok, "")
            return status, nil
        }
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

<Note>
If your process exits right after creating spans, flush the tracer provider before exit. In Python, call `tracer_provider.shutdown()`. In JS/TS, call `provider.shutdown()`. In Go, call `tp.Shutdown(ctx)`.
</Note>

## What to instrument

Manual spans work best when they explain the custom parts of your application.

| Span kind | Use it for |
| --------- | ---------- |
| `CHAIN` | Routing, preprocessing, postprocessing, and pipeline steps |
| `AGENT` | An agent run that may contain model calls and tool calls |
| `TOOL` | A function, API call, or tool invoked by an agent |
| `RETRIEVER` | A search or retrieval call that returns documents |
| `RERANKER` | A reranking step for retrieved documents |
| `LLM` | A model call when no auto-instrumentor is available |

Use [Auto-instrumentation](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-using-phoenix-otel) for supported LLM clients whenever possible. Manual `LLM` spans are useful for custom clients and unsupported SDKs.

## Learn more

- **Choose the right span kind:** span kinds tell Phoenix how to display each operation. See [OpenInference span kinds](/docs/phoenix/tracing/concepts-tracing/otel-openinference/span-kinds).

- **Group traces into conversations:** add `session.id` and `user.id` to follow multi-turn interactions. See [Set up sessions](/docs/phoenix/tracing/how-to-tracing/setup-tracing/setup-sessions).

- **Enrich manual spans:** attach metadata, tags, prompt templates, and custom attributes. See [Customize your traces](/docs/phoenix/tracing/how-to-tracing/add-metadata/customize-spans).

- **Capture multimodal content:** attach images and audio as span attributes. See [Capture multimodal traces](/docs/phoenix/tracing/how-to-tracing/advanced/multimodal-tracing).

- **Control what is captured:** hide sensitive inputs, suppress tracing for specific calls, or redact span attributes. See [Mask and redact data](/docs/phoenix/tracing/how-to-tracing/advanced/masking-span-attributes).

- **Tune the SDK setup:** configure batching, custom endpoints, headers, sampling, and full SDK options. See [Python arize-phoenix-otel](/docs/phoenix/sdk-api-reference/python/arize-phoenix-otel), [TypeScript @arizeai/phoenix-otel](/docs/phoenix/sdk-api-reference/typescript/arizeai-phoenix-otel), or [TypeScript tracing helpers](/docs/phoenix/sdk-api-reference/typescript/packages/phoenix-otel/tracing-helpers).
