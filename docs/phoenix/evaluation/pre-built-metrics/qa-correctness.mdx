## Overview

The **Q&A Correctness** evaluator determines whether an answer correctly and completely answers a question, using a reference text as the source of truth. It is a system-level check for question-answering and RAG applications: given the question, the system's answer, and the reference material the answer should be based on, it judges whether the question was actually answered correctly.

### When to Use

Use the Q&A Correctness evaluator when you need to:

- **Evaluate a RAG or Q&A system end to end** - Check whether the final answer correctly answers the user's question given the retrieved context
- **Catch partial or wrong answers** - Detect answers that address the wrong question, omit key information, or contradict the reference
- **Measure answer quality against ground truth** - Compare answers to a known reference rather than to general world knowledge

<Info>
Q&A Correctness judges whether the answer *correctly answers the question* against the reference. This is different from [Faithfulness](/docs/phoenix/evaluation/pre-built-metrics/faithfulness), which checks whether the answer is *grounded* in the context (does not fabricate), and from [Document Relevance](/docs/phoenix/evaluation/pre-built-metrics/document-relevance), which checks whether retrieved documents are relevant. An answer can be faithful yet still fail to answer the question.
</Info>

## Supported Levels

The level of an evaluator determines the scope of the evaluation in OpenTelemetry terms. Some evaluations are applicable to individual spans, some to full traces or sessions, and some are applicable at multiple levels.

| Level | Supported | Notes |
|-------|-----------|-------|
| **Span** | Yes | Apply to the span where the question (`input`), the answer (`output`), and the reference are available — typically the root span of a Q&A trace. |

**Relevant span kinds:** LLM and chain spans in Q&A or RAG pipelines, particularly the root span whose input/output represent the question and the final answer.

## Input Requirements

The Q&A Correctness evaluator requires three inputs:

| Field | Type | Description |
|-------|------|-------------|
| `input` | `string` | The question the answer is responding to |
| `output` | `string` | The answer to evaluate |
| `reference` | `string` | The reference text used as the source of truth |

### Formatting Tips

For best results:

- **Use human-readable strings** rather than raw JSON for all inputs
- **For multiple retrieved documents**, concatenate them into a single `reference` string with clear separators (see [Input Mapping](#using-input-mapping) below):
  ```
  Our return policy allows returns within 30 days of purchase.

  Refunds are processed within 5 business days.
  ```

## Output Interpretation

The evaluator returns a `Score` object with the following properties:

| Property | Value | Description |
|----------|-------|-------------|
| `label` | `"correct"` or `"incorrect"` | Classification result |
| `score` | `1.0` or `0.0` | Numeric score (1.0 = correct, 0.0 = incorrect) |
| `explanation` | `string` | LLM-generated reasoning for the classification |
| `direction` | `"maximize"` | Higher scores are better |
| `metadata` | `object` | Additional information such as the model name. When tracing is enabled, includes the `trace_id` for the evaluation. |

**Interpretation:**
- **Correct (1.0)**: The answer correctly and fully answers the question and is consistent with the reference
- **Incorrect (0.0)**: The answer is wrong, partial, off-topic, or contradicts or is unsupported by the reference

## Usage Examples

<Tabs>
  <Tab title="Python" icon="python">
    ```python
    from phoenix.evals import LLM
    from phoenix.evals.metrics import QACorrectnessEvaluator

    # Initialize the LLM client
    llm = LLM(provider="openai", model="gpt-4o")

    # Create the evaluator
    qa_correctness_eval = QACorrectnessEvaluator(llm=llm)

    # Inspect the evaluator's requirements
    print(qa_correctness_eval.describe())

    # Evaluate a single example
    eval_input = {
        "input": "What is the capital of France?",
        "output": "The capital of France is Paris.",
        "reference": "Paris is the capital and largest city of France.",
    }

    scores = qa_correctness_eval.evaluate(eval_input)
    print(scores[0])
    # Score(name='qa_correctness', score=1.0, label='correct', ...)
    ```
  </Tab>

  <Tab title="TypeScript" icon="js">
    ```typescript
    import { createQACorrectnessEvaluator } from "@arizeai/phoenix-evals";
    import { openai } from "@ai-sdk/openai";

    // Create the evaluator
    const qaCorrectnessEvaluator = createQACorrectnessEvaluator({
      model: openai("gpt-4o"),
    });

    // Evaluate an example
    const result = await qaCorrectnessEvaluator.evaluate({
      input: "What is the capital of France?",
      output: "The capital of France is Paris.",
      reference: "Paris is the capital and largest city of France.",
    });

    console.log(result);
    // { score: 1, label: "correct", explanation: "..." }
    ```
  </Tab>
</Tabs>

### Using Input Mapping

When your data has different field names or requires transformation, use input mapping. This is especially handy for RAG spans: the [span helpers](/docs/phoenix/tracing/how-to-tracing/importing-and-exporting-traces/extract-data-from-spans) can build a DataFrame with `input`, `output`, and `context` columns, and you map `context` onto `reference`.

<Tabs>
  <Tab title="Python" icon="python">
    ```python
    from phoenix.evals import LLM
    from phoenix.evals.metrics import QACorrectnessEvaluator

    llm = LLM(provider="openai", model="gpt-4o")
    qa_correctness_eval = QACorrectnessEvaluator(llm=llm)

    # Example with nested data and multiple documents
    eval_input = {
        "input": {"query": "What is the return policy?"},
        "output": {"response": "You can return items within 30 days."},
        "retrieved": {
            "documents": [
                "Our return policy allows returns within 30 days.",
                "Refunds are processed within 5 business days.",
            ]
        },
    }

    # Use input mapping with a lambda to concatenate documents into the reference
    input_mapping = {
        "input": "input.query",
        "output": "output.response",
        "reference": lambda x: "\n\n".join(x["retrieved"]["documents"]),
    }

    scores = qa_correctness_eval.evaluate(eval_input, input_mapping)
    ```

    For more details on input mapping options, see [Input Mapping](/docs/phoenix/evaluation/concepts-evals/input-mapping).
  </Tab>

  <Tab title="TypeScript" icon="js">
    ```typescript
    import { bindEvaluator, createQACorrectnessEvaluator } from "@arizeai/phoenix-evals";
    import { openai } from "@ai-sdk/openai";

    const qaCorrectnessEvaluator = createQACorrectnessEvaluator({
      model: openai("gpt-4o"),
    });

    // Bind with input mapping for different field names
    const boundEvaluator = bindEvaluator(qaCorrectnessEvaluator, {
      inputMapping: {
        input: "question",
        output: "answer",
        reference: (data) => data.documents.join("\n\n"),
      },
    });

    const result = await boundEvaluator.evaluate({
      question: "What is the return policy?",
      answer: "You can return items within 30 days.",
      documents: [
        "Our return policy allows returns within 30 days.",
        "Refunds are processed within 5 business days.",
      ],
    });
    ```

    For more details on input mapping options, see [Input Mapping](/docs/phoenix/evaluation/concepts-evals/input-mapping).
  </Tab>
</Tabs>

### Viewing and Modifying the Prompt

You can view the latest versions of our prompt templates [on GitHub](https://github.com/Arize-ai/phoenix/blob/main/prompts/classification_evaluator_configs/QA_CORRECTNESS_CLASSIFICATION_EVALUATOR_CONFIG.yaml). The evaluators are designed to work well in a variety of contexts, but we highly recommend modifying the prompt to be more specific to your use case. Feel free to adapt them.

<Tabs>
  <Tab title="Python" icon="python">
    ```python
    from phoenix.evals.metrics import QACorrectnessEvaluator
    from phoenix.evals import LLM, ClassificationEvaluator

    llm = LLM(provider="openai", model="gpt-4o")
    evaluator = QACorrectnessEvaluator(llm=llm)

    # View the prompt template
    print(evaluator.prompt_template)

    # Create a custom evaluator based on the built-in template
    custom_evaluator = ClassificationEvaluator(
        name="qa_correctness",
        prompt_template=evaluator.prompt_template,  # Modify as needed
        llm=llm,
        choices={"correct": 1.0, "incorrect": 0.0},
        direction="maximize",
    )
    ```
  </Tab>

  <Tab title="TypeScript" icon="js">
    ```typescript
    import { QA_CORRECTNESS_CLASSIFICATION_EVALUATOR_CONFIG, createQACorrectnessEvaluator } from "@arizeai/phoenix-evals";
    import { openai } from "@ai-sdk/openai";

    // View the prompt template
    console.log(QA_CORRECTNESS_CLASSIFICATION_EVALUATOR_CONFIG.template);

    // Create a custom evaluator with a modified template
    const customEvaluator = createQACorrectnessEvaluator({
      model: openai("gpt-4o"),
      promptTemplate: QA_CORRECTNESS_CLASSIFICATION_EVALUATOR_CONFIG.template, // Modify as needed
    });
    ```
