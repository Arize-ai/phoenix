Use metrics and dashboards when you want to see whether latency, cost, errors, token usage, or annotation scores changed before you open individual traces.

Phoenix project metrics are predefined. Each project has a **Metrics** tab, and the global **Dashboards** page lets you select a project and review the same kind of project-level trends.

## Open project metrics

Open a project and select **Metrics**. Use the time range control to focus on the period you want to review.

## Open dashboards

In the Phoenix app, select **Dashboards** from the sidebar. Choose a project from the project dropdown, then set the time range for the charts.

Phoenix remembers your last selected dashboard project and opens it the next time you return to Dashboards.

## What Phoenix shows

Phoenix indexes traces for metrics after they are sent to a project. Each project dashboard includes these charts by default:

- **Traces** over time
- **Trace latency** percentiles
- **Cost** estimated in USD
- **Top models by cost**
- **Top models by tokens**
- **Token usage** by prompt and completion
- **Prompt token details** by input, cache, and audio parts
- **Completion token details** including output, reasoning, and audio parts
- **LLM spans** over time
- **LLM span errors** over time
- **Tool spans** over time
- **Tool span errors** over time
- **Span annotation scores**
- **Trace annotation scores**
- **Session annotation scores**

## When to use metrics and dashboards

Use metrics and dashboards to spot changes in trace data, such as latency spikes, cost changes, tool failures, or falling annotation scores. Use the project tables and filters when you need to find the traces behind those changes.

<Info>
Phoenix supports trace inspection, PXI-assisted investigation, project metrics, dashboards, and data export. For custom metrics, monitors, alerts, Signal, and managed production workflows, use [Arize AX](https://arize.com/docs/ax/observe).
</Info>
