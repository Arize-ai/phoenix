---
title: "What is my Phoenix Endpoint?"
---


Your Phoenix instance has one URL, and two environment variables point at it — one per concern:

1. **API access** — `PHOENIX_ENDPOINT`. Read by the Phoenix clients, the `px` CLI, and MCP to query traces, log annotations, and retrieve prompts.
2. **Trace export** — `PHOENIX_COLLECTOR_ENDPOINT`. Where your instrumented application sends OpenTelemetry traces.

You choose the URL itself when you set up the app. For a local `phoenix serve` it is `http://localhost:6006`. For a remote deployment it is under the `Hostname` field of the **Settings** page.

### API access — `PHOENIX_ENDPOINT`

Always a plain base URL, with no request path: the clients and the CLI append their own.

```bash
export PHOENIX_ENDPOINT=http://localhost:6006
```

If you have only ever set `PHOENIX_COLLECTOR_ENDPOINT`, that keeps working — API access falls back to it.

### Trace export — `PHOENIX_COLLECTOR_ENDPOINT`

This one accepts either the base URL or the full OTLP trace endpoint. Which shape you want depends on the exporter reading it:

* **`register()`** derives the OTLP target itself, so give it the base URL:

  ```bash
  export PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006
  ```

  Left to infer, Python's `register()` sends over OTLP/gRPC on port `4317` for self-hosted servers; pass `protocol="http/protobuf"` to send over HTTP instead. The TypeScript SDK always uses OTLP/HTTP.

* **Exporters that POST to exactly the URL they are given** — a bare `OTLPSpanExporter`, Mastra's `ArizeExporter` — need the full OTLP/HTTP URL:

  ```bash
  export PHOENIX_COLLECTOR_ENDPOINT=http://localhost:6006/v1/traces
  ```

You can also skip the variable and pass the target to `register()` directly, as `register(endpoint="http://localhost:6006/v1/traces")`.

<Tip>
In the common case one Phoenix serves both concerns, so set both variables to the same base URL — which is what `px setup` writes into `.env.phoenix`. Set them to different values only when trace ingest and API access genuinely live at different addresses.
</Tip>

For every connection setting and the order each one resolves in, see [Environments](/docs/phoenix/environments).
