Dimension 1: rework and competing work

The path overlap looks small on paper, but main moved most of the old monolith into new files while the local branch continued changing the same responsibilities in place.

Highest leverage

Use main's trace/span/ layer as the substrate

Commit ec7865195 extracts focused renderers such as LLMInput, RerankerInput, SpanIO, and SpanAttributesCard. It also adds a Relay-independent SpanInfoData shape, pure parsers/getters, unit tests, realistic stories, and a barrel export.

Reapply the local flat section shell around those components. Retaining the roughly 2,000-line local SpanDetails.tsx would duplicate landed work and preserve obsolete ownership.

Tab reduction is complementary

The local branch removes top-level span tabs. Main removes nested LLM tabs. Keep both ideas: main's LLM view selector inside the local branch's flat Info section.

Normalize cards before porting stories

Adopt main's Input/Output vocabulary, inline subtitles, shared document-list styles, and parent-header raw controls. Then update the local stories to the new visual structure.

Consolidate overlapping Storybook matrices

Main's fixtures are strongest as the canonical functional matrix. The local suite adds the valuable stress dimension: long values, excessive tools/documents, narrow panels, malformed attributes, and composed drawer states.

Preserve orthogonal local fixes

ID truncation, annotation-label overflow, presentational event and annotation exports, pixel sizing, narrow trace-tree support, and composition stories are not superseded by the reviewed main commits.

Dimension 2: actual incompatibility

Product decision required: choose the resizable annotation rail or the fixed annotation bar. Keeping both creates two editors, duplicate fetching/mutations, competing keyboard behavior, and layout pressure.

Annotation ownership is the fundamental fork

Main moves the session resizable group above the metrics header so its annotation rail spans the full drawer. Main's span view also retains SpanAside, the annotate toggle, hotkey, persisted preference, and collapsible panel.

The local branch deliberately removes those rails and adds a fixed horizontal annotation bar. Its own follow-up notes acknowledge that trace/session status, tokens, cost, latency, and the direct “View Session” action disappear with the old headers. If the fixed bar wins, those metrics need an intentional new home.

SpanDetails.tsx cannot be merged mechanically

Main imports canonical components from ./span; the local file still defines and exports its own renderers. Main also moved SpanImage. Keep the extracted ownership and port the flat layout, rather than retaining both sets of symbols.

Local stories need new imports and types

They currently import SpanInfo, SpanIO, SpanAttributes, and a Relay-derived type from SpanDetails. Main's canonical exports and structural type now live under @phoenix/pages/trace/span.

SessionDetails.tsx is semantic, not just textual

Main queries and renders metrics plus the side rail. The local branch queries only the view data and puts the fixed bar above the tabs. Resolve the product model first, then write one coherent query/layout.

Regenerate Relay artifacts

Generated query files may auto-merge without matching the resolved source graph. Regenerate them after the source architecture is settled; do not treat a clean generated-file merge as proof.

Confirmed non-conflicts
  • Main's session-turn width change and the local presentational export auto-merge.
  • The OTLP selection-download work is compatible with the local narrow-tree work.
  • The drawer pixel-sizing work does not textually conflict with the reviewed main window.
  • Main's Card and DocumentItem changes are additive; local visual expectations simply need rebaselining.

Recommended integration order

  1. Bring in main and accept trace/span/ as canonical.
  2. Choose the annotation model before resolving SessionDetails.tsx.
  3. Rebuild the flat top-level sections around main's extracted span components.
  4. Port complementary stress fixtures; avoid two complete span-kind story matrices.
  5. Preserve orthogonal local fixes as separable commits where possible.
  6. Regenerate Relay output, then run typecheck, unit, Storybook, and visual checks.
The flat-drawer idea remains valuable. Anchor navigation, stacked sections, fixed context, narrow sizing, and stress coverage are not present on main.
The old implementation substrate does not. Main's pure component layer should replace the local monolithic span renderer. The annotation interaction model is the only fundamental incompatibility.
