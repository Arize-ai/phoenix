Add an `evaluators` subpath for shared evaluator definitions over REST (Phoenix server >= 21.0.0): `getEvaluators` lists definitions with `type: "llm" | "code"`, `name`, and `limit`; `getEvaluator` reads one; `createEvaluator` creates an unbound definition discriminated by `type`, pinning an LLM evaluator to an existing prompt version with `prompt: { selector: { type: "version", prompt_version_id } }`; `updateEvaluator` takes a patch discriminated the same way and moves an LLM evaluator between prompt versions through the same `prompt.selector`; `deleteEvaluator` deletes an unbound LLM or code evaluator, keeping an LLM evaluator's prompt; `getCodeEvaluatorVersions` lists a code evaluator's history; `createCodeEvaluatorVersion` appends immutable code, optionally with the configuration it needs and an `expectedCurrentVersionId` guard, reporting `was_created`; and `getSandboxConfigs` lists the sandboxes code evaluators can run in. A failed request throws `HttpError` whose `problem` carries the server's `code`, a finer `reason` when it sends one, and recovery fields such as `existing_id` or `binding_counts`. The definition, patch, create, version, sandbox config, input mapping, and output configuration types are exported from the same subpath.
