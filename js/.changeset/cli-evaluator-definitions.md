Add `px evaluator list|get|create|update|delete`, `px evaluator version list|create`, and `px sandbox-config list` for shared evaluator definitions (Phoenix server >= 21.0.0). `list` filters by `--type llm|code` and `--name` and caps results with `--limit`. `create --type llm|code` makes a definition that nothing binds yet: an LLM evaluator pins an existing prompt version with `--prompt-version-id`, a code evaluator is created with its first version, and `--if-not-exists` prints the evaluator already holding a taken name instead of failing. `update` takes only the field flags to change, clears fields with `--clear-description` and `--clear-sandbox-config`, moves an LLM evaluator between prompt versions with `--prompt-version-id`, and rejects flags that belong to the other kind before calling the server. `delete` removes an unbound LLM or code evaluator behind the deletes gate, keeping an LLM evaluator's prompt. `version create` appends immutable code from `--file` or `--source-code`, can apply the sandbox, input mapping, outputs, or description the new code needs in the same request, and refuses to race another deploy with `--expected-current-version`. Every command checks the server version before calling it and validates `--format`; a refusal on stderr in `raw`/`json` mode carries `status`, `problem_code`, a finer `problem_reason` when the server sends one, and the full `problem` body.
