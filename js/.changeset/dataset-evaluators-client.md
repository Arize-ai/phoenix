Add dataset evaluator bindings to the `evaluators` subpath: `createDatasetEvaluator`, `getDatasetEvaluators`, `getDatasetEvaluator`, `updateDatasetEvaluator`, `deleteDatasetEvaluator`, and `deleteDatasetEvaluators` (Phoenix server >= 21.0.0). Datasets are selected by `dataset`, `datasetId`, or `datasetName`. `createDatasetEvaluator` requires `evaluatorId` (an existing LLM, code, built-in, or decision evaluator; create an LLM or code one first with `createEvaluator`), `evaluatorType` (`"llm"`, `"code"`, `"builtin"`, or `"decision"`, matching the evaluator's kind; the server refuses a mismatch), and `inputMapping`. `updateDatasetEvaluator`'s patch carries the same `evaluator_type`. An `outputConfigs` override holds at least one config and a `description` is a string; a `null` on `updateDatasetEvaluator`'s patch restores inheritance from the shared definition instead. An LLM binding's output overrides are categorical, and a decision binding takes no output config override, since its outputs follow the evaluator's questions and scoring policy. Deleting a binding removes its dedicated evaluator trace project and the recorded evaluator traces stored there, while keeping the shared definition, prompt, and dataset. `deleteDatasetEvaluators` takes the dataset and sends the ids as repeated `dataset_evaluator_id` query parameters, atomically. `EvaluatorDefinition` and `EvaluatorType` now include the read-only built-in variant.
