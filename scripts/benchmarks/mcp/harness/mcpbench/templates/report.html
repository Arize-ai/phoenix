MCP surface benchmark

What this is

An AI agent was asked the same questions twice over — once through each way Phoenix can expose its tools over MCP. Everything else was held identical: same model, same questions, no system prompt, no built-in tools. The only thing that differs between labelled runs is the tool surface.

What's measured is context tokens — how much text the model had to read to answer. Tokens are what you pay for and what fills the model's limited working memory, so fewer is better, but only if the answer is still right. Every number below counts only runs that answered correctly.

What the numbers mean

Context tokens
Everything the model had to read to produce its answer — the tool descriptions, the question, and every result handed back to it. This is the headline number: it is what you are billed for and what competes for the model's limited working memory.
Peak context
The largest single moment, rather than the total. A run can be cheap overall yet still spike past a smaller model's limit.
Turns
How many times the model went back to the server before answering. More turns usually means it was searching, or recovering from a mistake.
Tool calls / discovery calls
Tools the model invoked. Discovery calls are the ones spent finding out what tools exist — overhead paid before any real work starts.
Passed
Whether the answer matched the expected one. A cheap label that answers wrongly is not cheap, so unpassed runs are excluded from the comparisons.
